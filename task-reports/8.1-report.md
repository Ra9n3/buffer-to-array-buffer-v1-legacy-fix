## 2. What was built

1. **One shared transport controller** (`src/lib/playback/controller.ts`) owning
   play/pause/stop/seek, listening source, playhead, duration, render progress and error.
2. **One reactive facade** (`src/lib/playback/store.svelte.ts`) attached once by the
   project shell. The mini transport and the live Console deck read the same state.
3. **Raw synchronized playback** of imported stems through the 5.1 asset store and 7.4
   WAV source adapter, unity-summed with shared mute/solo audibility.
4. **Lightweight live preview** through the existing `MixEngine`, including buses,
   Returns, sends and sidechains, with limiter-latency compensation.
5. **Full rendered-mix playback** through Task 7.4 `renderProject`, streamed with
   backpressure and cancellation/failure recovery.
6. **A bounded Web Audio backend** (`src/lib/playback/web-audio.ts`) that schedules
   short chunks on the audio clock and stops/disconnects stale generations.
7. **Room integration**: the Console deck is live; Arrange and Mixer use the persistent
   mini transport. No room owns playback state.

## 4. Architecture and modules reused

- **Project state:** the one Task 3.1 store. No project-model or persistence field was
  added. Transport state is transient app state, not saved in the manifest.
- **Imported audio:** Task 5.1 `AssetStore` and Task 7.4 `openWavRenderSource`; no stem
  is decoded whole. Mono is duplicated to stereo by the existing adapter.
- **DSP/routing:** Task 7.1 `MixEngine` and `computeAudibility`; Task 7.2 sidechains and
  Task 7.3 masking overlays are preserved because preview/render use the same engine.
- **Rendering:** Task 7.4 `renderProject` is the only rendered-mix producer. Playback
  supplies a streaming sink; it does not duplicate rendering or DSP.
- **UI:** existing `MiniTransport`, `ConsoleTransport`, `TactileSwitch`, `LampDisplay`,
  `MixButton`. No new layout, styling system or source selector.

## 5. State and synchronization behavior

- **Play:** starts/resumes the current source at the playhead. If at the end, restarts
  from the defined start.
- **Pause:** stops scheduled audio, keeps the playhead, and discards the current DSP
  attempt. Resume reinitializes at the paused frame.
- **Stop:** returns to `startFrame` (frame 0) and discards scheduled audio/DSP state.
- **Seek:** clamps to the known duration, stops the current generation, and restarts at
  the target if playback was running. Previous/Next locate to start/end.
- **Rooms:** the mini transport is rendered once outside the room switch; the Console
  deck reads the same facade. Switching rooms preserves status and playhead.
- **Mute/solo:** RAW re-reads `computeAudibility` each block; PREVIEW calls
  `engine.refreshAudibility()` each block. Mute wins; solo-in-place is unchanged.
- **Source:** remains status text (D2.3.2). RAW is the default; PREVIEW is available
  through the facade; MIX starts RENDER. No selector was added.

## 6. Buffering and memory strategy

- RAW/PREVIEW block: **2048 frames** by default. Render orchestration block: **4096
  frames** (Task 7.4 default).
- Producers read frame ranges into reused buffers. No duration-proportional stem or mix
  buffer is allocated.
- The Web Audio backend schedules short chunks and applies backpressure at roughly
  **1 second** of queued audio. A generation counter plus `stop()`/`disconnect()`
  prevents stale scheduled audio after pause/seek/stop/restart.
- The allocation test instruments `Float32Array` construction and proves identical
  allocation for short and long RAW/PREVIEW sessions.

## 8. Known limitations

- **Source selection is not a new UI control.** D2.3.2 remains: the source is printed as
  text. MIX starts the rendered path; PREVIEW is available through the shared facade.
- **Preview parameter edits:** mute/solo is live without a rebuild. Graph/chain parameter
  edits are heard on a new attempt, matching the 7.1 lifecycle contract.
- **Rendered seek is safe restart.** A seek/restart discards output before the target and
  re-renders from the project start; no persisted checkpoint or full mix cache exists.
- **No export.** WAV/stem/bus export and dialogs remain Task 8.2.
- **No browser listening evidence in this report.** Verification is deterministic Node
  tests, structural guards, type check and production build. The running app is ready
  for owner review.
