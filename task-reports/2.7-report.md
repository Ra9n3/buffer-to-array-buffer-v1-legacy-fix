## Shared components — reused / modified

**Reused as-is (no change):** `Knob`, `Fader`, `TactileSwitch`, `Lamp`,
`EngravedLabel`, `SendSlot`, both fixture files, the Console's
`ChannelBank` (its CSS copied, the file untouched).

**Modified, backward-compatible, each an optional addition with a default
that reproduces the approved behaviour exactly:**

1. **`TrackStrip.svelte` — `identity?: Snippet`.** Rationale: plan §3
   keeps tagging and tiers off the Console strip while §5a puts the tier on
   the Mixer strip; the owner chose one extra section under the head rather
   than a second strip design (D2.7.1). Impact: without the prop the
   template and CSS are the Task 2.2 strip (the `{#if identity}` block
   renders nothing; the new CSS rule matches nothing); the Console bank
   passes nothing and measured identical. One new section name,
   `data-strip-section="identity"`, between `head` and `trim`.
2. **`StripModule.svelte` — `identity?: Snippet | null` (default null).**
   The same section in the pinned module's chassis, before the first knob.
   Same impact.
3. **`ReturnStrip.svelte`, `BusMasterStrip.svelte` — `identity` forwarded**
   (default null). No other change.
4. **`ScribbleSelect.svelte` — `onchoose?: (id) => void` (default null).**
   Rationale: `choose()` only fires `onchange` when the value changes, so
   re-choosing the shown tier could not confirm it; the owner approved this
   small callback over a pseudo-option (D2.7.1). Impact: `onchoose?.(id)`
   runs after the unchanged `if (id !== value) { value = id; onchange?.(id); }`
   — callers without it see exactly the approved behaviour; the Arrange
   row's geometry was measured identical before and after.
5. **`lib/arrange.ts` — `tierConfirmed?: boolean`.** Optional, absent =
   confirmed; only 09 and 16 set it. `ArrangeTrackRow` does not read it
   (D2.5.1 stands: the Arrange row does not draw "needs confirmation").

## Deviations and follow-ups

1. **Identity section 81 px, not the ≈ 56 px estimated with the
   questions** (D2.7.2): measured in the strip's own type, the one-line
   "FAMILY · SOURCE" print does not fit the 144 px inside width on four
   tracks (178 / 160 / 144 px), so family and source are two lines. The
   strip is 755.5 px (+ 12 %) — taller than the Console's 674.4 px, which
   is expected: the Mixer strip carries more.
2. **Detail panel below the fold at common heights.** With the bank 755 px
   tall plus legends and the room header, the Task 0.5 panel starts
   below a 1000 px-tall viewport in every width (the layout scrolls
   vertically; the panel keeps its own internal scroll and a 24rem floor).
   Inherent in the owner's stacked choice; **Task 2.9** (the detail panel)
   is the place to revisit the split (e.g. a side-by-side at ≥ 1920, or a
   collapsible bank).
3. **Tier and selection are per-room UI state.** The Arrange row and the
   Mixer strip each hold their own copy of the tier; confirming in the
   Mixer does not reach Arrange, and nothing is persisted — the shared
   project model (Task 3.1) owns that. The detail panel is still the
   Phase 0 panel and not kind-aware (Task 2.9).
4. **Numeric Priority override** (plan §5a) is not drawn — follow-up when
   the owner wants it; the identity section has no spare row for it at
   160 px, so it would need either a fourth row or the detail panel.
5. **Family / source editing in the Mixer** (plan §5a's combobox "in the
   same locations as Arrange") is deliberately a print here (owner,
   D2.7.1); if editing is wanted later, two windows need a wider strip or
   another row.
6. **Longest catalog labels truncate** in the 144 px source line
   ("Distorted Electric Guitar", 10 and 11; tooltip carries the full
   name) — the approved name-head behaviour; a shorter catalog label is
