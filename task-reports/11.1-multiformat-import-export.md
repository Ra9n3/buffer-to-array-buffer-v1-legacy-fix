# Task 11.1 — multi-format audio: one internal format, one project rate

**Owner instruction of 2026-11-14** (scope as received; the brief's clauses are
carried by the decisions D11.1.1–D11.1.7):

- multi-format audio — 24-bit and 32-bit × 44.1 and 48 kHz — on both the import
  and the export side;
- one internal format (32-bit float) and one project sample rate
  (44.1 | 48 kHz, default 48000, chosen at creation and locked);
- import converts once, export converts once; rate conversion and depth
  conversion are separate stages;
- resampling is never claimed lossless — every path that resamples says so;
- the import parser handles packed 24-bit and WAVE_FORMAT_EXTENSIBLE 24-in-32;
  refusals keep the "convert or re-export" advice.

Decisions **D11.1.1–D11.1.7** in `decisions-log.md`. One commit on the
`console-redesign` branch (Task 10.2's fix commit is its parent). 58 files
changed (+2393 / −460) and 11 new paths: the eight new modules and panels,
the resample test, and the evidence directory.

## 1. What changed

| Where | Before (10.2) | After (this task) |
| --- | --- | --- |
| Rate decisions | `48000` written in the modules that needed it (`dsp/params`' `DSP_SAMPLE_RATE`, the mixer-chain response, the benchmark) | **`lib/audio/rates.ts`** — the one home: `ProjectRate`, `PROJECT_RATES` (44100, 48000), `DEFAULT_PROJECT_RATE` (48000), `LEGACY_PROJECT_RATE` (48000 — what every pre-11.1 project was built at), the internal-format constants, the prints. `DSP_SAMPLE_RATE` derives from it (D11.1.1) |
| Import acceptance | 48 kHz · 24-bit PCM or 32-bit float · mono/stereo; everything else refused with the 48 kHz advice; "nothing here converts, resamples or dithers" | **either rate, four depth layouts** — 24-bit packed, 24-in-32 (both alignments), 32-bit int, 32-bit float; the new advice names both rates and all four layouts. Still refused, each named: 16-bit, 8-bit, 96 kHz, >2 channels (mask read and described first), compressed |
| 24-in-32 | read as whatever the container said — no alignment rule | **left-aligned by the declared rule** (Microsoft ksmedia.h: valid bits are left-aligned, pad zeroed), word `>> 8` scaled by 2^23; **one deterministic whole-file override** when every word has a zero high byte and some word a non-zero low byte — right-aligned. The resolved alignment and its basis ("declared" \| "detected") travel in `AssetRecord.format` and `TrackAudio` (D11.1.3) |
| The import stage | read → store → peaks from the original | **`lib/audio/convert.ts`**: parse → resample to the project rate (only when the rates differ) → peaks FROM THE CONVERTED COPY. The store keeps the original bytes AND its facts beside the converted copy (32-bit float WAV at the project rate, the one writer, `decoded` mode) — non-destructive. Peaks keyed to the converted hash and rate; a mismatch invalidates them (D11.1.4) |
| Where the stage runs | in-thread | **a Worker** (`lib/audio/import.worker.ts`, `?worker&inline` — the single-file build stays single); Node tests and a Worker-less browser fall back to the in-thread stage |
| The resampler | none — a rate mismatch was a refusal | **`lib/audio/resample.ts`**: polyphase windowed-sinc, Kaiser (96 dB stopband, β ≈ 9.6), 64 taps/phase, cutoff 0.925 × min(rate)/2. Ratios reduced and pinned: 48→44.1 is 147/160, 44.1→48 is 160/147. Group delay compensated by construction; the residue declared once: 32 input samples of lookahead, zero-padded at the end (the last ~0.7 ms fades). Per-phase DC normalisation; streaming and whole-file byte-identical (D11.1.5) |
| Export | rendered at the DSP rate (48000); float default, 24-bit supported; one format select | **renders at `project.sampleRate`**; when the target differs, `RateStageWriter` (`lib/export/rate-stage.ts`) streams the render through the same resampler, then the one WAV writer applies the depth. `ExportDialog.svelte`: two independent selects — depth (24-bit PCM \| 32-bit float) × rate (44.1 \| 48 \| the project's own, the default) — four combinations, remembered in settings with the dither choice (D11.1.6) |
| 24-bit export | round-to-nearest, symmetric clamp | **same conversion, plus TPDF dither as an explicit opt-in**, applied ONCE at the depth stage — never on the float path, never double, no noise shaping; an injectable noise source keeps the tests deterministic. `fact` chunk: omitted for 24-bit PCM, included for float (44 + 12); every header field golden-pinned for all four combinations |
| The project's rate | not a field — the app was 48000 by construction | **`Project.sampleRate`**, chosen at creation (default 48000) and locked; the manifest writes it; a manifest without it (pre-11.1) reopens at `LEGACY_PROJECT_RATE` 48000 — which is what those projects were built at. The Web Audio context is created at the project's rate where the browser allows it; the device rate is Web Audio's, not ours (D11.1.2) |
| Changing it | impossible | **`lib/project/rate-change.ts`** — the only door is the Settings panel (`ProjectRatePanel.svelte`): every original read and hash-checked first, each converted at the new rate with per-stem progress, then the project's rate and every track's audio facts flip in ONE structural change — the project is never seen at the new rate with the old copies. A same-rate call is an honest no-op. Analysis results are NOT invalidated (they measure the original's content). A half-applied change self-heals on the next hydrate (D11.1.7) |
| The import line | said what the file was | **says what happened**: "44.1 kHz → 48 kHz — high-quality resampling to the project rate — not lossless". The same honest note travels in the export outcome |

## 2. Measured, not asserted — pinned to files

All three artifacts live in `task-reports/evidence/11.1/`; each is re-read and
re-checked by the suite on every run, not eyeballed once.

**`golden-export-headers.json`** — every header field of all four export
combinations (float32@48000, pcm24@48000, float32@44100, pcm24@44100),
golden-pinned: the tests fail if a field moves.

**`import-fixtures/`** — six real files (24-44100, 24-48000, 24-in-32 left and
right @48000, 32f-44100, 32f-48000) with a manifest that records, per file:
the source facts, the converted copy ("48000 Hz · 32-bit float · 96000
frames"), whether it was resampled, the rate the peaks were computed at, and
the peak (−6.02 dBFS in every case — the conversion preserves level; only a
rate change resamples).

**`impulse-alignment.json`** — the resampler's round-trip proof: both pinned
ratio specs (147/160 and 160/147, 64 taps/phase, cutoff 20396.25 Hz, 32 input
samples of lookahead) and the impulse cases — an impulse placed at a known
frame comes back at the same frame, `off: 0`, at both conversions; the
group-delay compensation is by construction, and this file is the receipt.

## 4. Said out loud

- The resampler is high quality, not lossless, and the UI says so at both
  doors — the import line and the export outcome. 20 kHz droops ≈ −3 dB at
  this tap budget; the transition band is ≈ 20.4–24.6 kHz wide; aliasing at
  the fold edge is ≥ 90 dB down. None of this is hidden.
- One documented edge case, not solved (D11.1.3): a left-aligned 24-in-32
  file that stays below −18 dBFS everywhere AND carries a noisy pad byte
  would read 256× too quiet — no header-only rule can separate it from a
  quiet right-aligned file. The override is deterministic; the residual is
  written down here rather than pretended away.
