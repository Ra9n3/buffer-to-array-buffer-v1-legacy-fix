## Summary

**What exists now**

- **Model** — plain typed shapes, no state, no values: kind-prefixed ids
  (`TrackId` `track-01`, `ReturnBusId` `return-room`, `BusId` `bus-B1`,
  constructors + type guards); typed references (`SendSlot.to:
  ReturnBusId | null`, `OutputRef = BusId | "master"`); `Track` (identity,
  TRK type, name, org, family, source type, Role, **Priority 1–10**,
  `tierConfirmed`, `output`, the Console strip's `channel` settings with
  four send slots, `loadedSendLevels`, the 2.8 `chain`, fixture `display`
  facts); `ReturnBus` (identity, effect, strip channel level · mute ·
  solo, the 2.9 effect chain, output); `Bus` (identity, strip channel
  trim · balance · level · mute · solo, the 2.9 bus chain, output);
  `Channel` union; `Arrangement` (bars, signature, sections, tempo
  markers, clips keyed by track id); `Project`. The Prominence Tier is a
  reading of the priority (`tierOfPriority`, bands 8–10 / 4–7 / 1–3;
  anchors 9 / 5 / 2 when a tier is chosen).
- **Store** — `const state: Project = $state(createSessionProject())`,
  the only project state in `src/`. `project` = reads and live selectors
  (`channels`, `channel(id)`, `tierOf`, `sendsInto`, `sendReturns`,
  `outputLabel`). `ops` = 20 narrow typed writes, one per editable control
  the approved UI has (track trim / pan / level / mute / solo, send `to` /
  level, family / source type with the 2.5 invariant, `chooseTrackTier`,
  `setTrackPriority`; Return level / mute / solo / bypass; bus trim /
  balance / level / mute / solo) — each validates its id (unknown ids
  throw), clamps to the control's range and skips same-value writes. Seven
  memoised views (`trackStrip`, `trackMeta`, `arrangeTrackOf`,
  `returnLive`, `returnStripOf`, `busStripOf`, `busLive`) are getter
  objects over the entities: the Console's strip and the Mixer's strip for
  the same channel bind the **same object**.
- **Session** — the approved fixtures only: `TRACK_STRIPS` joined to
  `ARRANGE_TRACKS` by code, `RETURN_STRIPS`, `BUS_MASTERS`, the three chain
  constructors, the 2.6 timeline data; priority = the fixture tier's
  anchor; outputs per the 2.4 reading (tracks → `bus-B1` → Master,
  Returns → Master). Nothing invented.
- **Rooms** — `ChannelBank` binds `trackStrip` / `returnStripOf` +
  `returnLive` / `busStripOf` + `busLive`; `ArrangeRoom` binds
  `arrangeTrackOf` + `trackMeta` and reads `project.arrangement`;
  `MixerBank` iterates `project.tracks / returns / buses`;
  `MixerTrackStrip` binds the same `trackStrip` view and reads family /
  source / role from the entity, tier through `trackMeta`;
  `MixerDetailPanel`, `ReturnDetail`, `BusDetail` read the entity and its
  chain (`sendsInto`, `outputLabel`). The Mixer's selection stays the
  room's own `$state` (an id into the store). `lib/mixer.ts` shrank to
  re-exports; `return-chain.svelte.ts` became the pure `return-chain.ts`.
- **Guards** — a new `check:project` (122 checks) and eight amended
  guards; 18 / 18, 1513 checks; `npm run check` 0 / 0; build OK.

**What did not change** — any pixel: strip 160 × 755.5, identity 81.1,
panel heights, the timeline, the Console bank, every hardware component
(pinned). Every fixture value and visual state. The approved interaction
behaviour (SEL radio, tier confirm via `onchoose`, ScribbleSelect, send
menus).

- **Which values are "project data"** when the plan lists only the engine's
  eventual inputs: the model keeps every value the approved UI shows and

  prompt forbids new UI). `ops.setTrackPriority` exists so it can be
  wired without a model change.
