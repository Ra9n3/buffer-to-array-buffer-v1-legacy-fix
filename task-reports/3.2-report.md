## Summary

**What exists now**

- **Routing module** `src/lib/project/routing.ts` (317 lines, new; pure —
  no Svelte, no state, no DOM, no writes). Nodes = the channels + Master;
  edges = every channel's one *output* edge and the tracks' *send* edges
  into Returns (`RoutingEdgeKind = "output" | "send"`; sidechain reserved
  as a documented future kind, not modelled). `validateRoute(project,
  source, to)` applies, in order: source exists → destination is Master or
  an **existing** bus (a track / Return id is "not a bus"; a missing bus id
  is dangling) → no self-route → a Return routes to Master only → the
  destination's output chain reaches Master without meeting the source
  (direct and indirect cycles; an already-looping chain is reported, never
  walked forever). Verdicts are values `{ ok, reason, message, path }`
  (six reason codes; messages "Routed: Kick → Master", "Unchanged: Mix Bus
  → Master", "Rejected: Bus B2 → Bus B1 → Bus B2 would loop", "Rejected:
  Return room is a Return — a Return always routes to Master (plan §8a)",
  …). `destinationsFor(project, id)` = Master first, then every bus, each
  with its verdict (the owner's "offer valid + explain rejected" API).
  `validateGraph(project)` = the same rules over a whole project
  (dangling outputs / sends, wrong-kind outputs, self-routes, Return
  outputs, DFS loop search). Also `routeOf`, `routingEdges`, `isRoutable`,
  `routingName`. It takes a structural `RoutingProject`, so the real
  `Project` and a three-line test fixture both satisfy it.
- **Model** — `SendSlot { to, level, mode: Mode }` (the 2.8 `Mode` type);
  the output references are unchanged in shape, their comments now point
  at the rules. Nothing else in `model.ts` changed.
- **Store** — reads `project.routeOf(id)`, `project.destinationsFor(id)`,
  `project.validateRouting()`; ops `setTrackOutput(id, to)` /
  `setBusOutput(id, to)` (validate on the untouched project, write only
  for `ok` **and** a changed reference, return the verdict; unknown source
  throws like every op; no Return output op), `setSendMode(id, slot,
  mode)`; `setSendLevel` makes an **assigned** send Manual on a real change;
  `setSendTo` decides the ownership of an assignment from the level already

### Where the documents are silent (assumptions — please correct any)

- **Rule order** (source → destination kind → self → Return → cycle) and
  the **wording** of the messages are builder choices; the field that
  prints them is a later task, so changing a message costs nothing now.
- **"Unchanged" is `ok`**: routing a channel to where it already is returns
  an accepted verdict with message "Unchanged: …" and writes nothing. The
  alternative (a distinct "no-op" verdict) seemed to add a third state the
  future field does not need.
- **Send ownership baseline** = the level the session loaded for that
  Return (`loadedSendLevels[to]`), else `DEFAULT_SEND_LEVEL` (−20 dB). The
  plan says sends have their own Auto / Manual but not what "original"
  means for a send that was never loaded; this reading needs no second
  stored value.
- **Ownership of a carried level** (assigning a slot whose level a hand had
  already moved) is **Manual**. The alternative — reset to Auto on every
  assignment — would silently discard a hand's value, which D2.8 forbids.
