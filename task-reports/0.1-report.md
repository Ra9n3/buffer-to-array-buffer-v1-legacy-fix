## What was built

### Application shell

`src/App.svelte` owns the shell:

- a persistent header with the ALLOY brand and room navigation;
- a content host (`<main id="main">`) that renders exactly one room at a time;
- the active room stored as Svelte state and synchronized with the URL hash.

The shell uses a CSS grid with a fixed header row and a flexible, scrollable room
row. `minmax(0, 1fr)` / `min-width: 0` constraints keep the shell within the
viewport at narrow widths. No room-specific layout is imposed on later tasks.

### Room navigation

`src/components/RoomNav.svelte` renders the three rooms from one definition list
in `src/lib/rooms.ts`:

| Room | Route | Purpose |
| --- | --- | --- |
| Console | `#/console` | Primary overview and automatic-mix workspace |
| Arrange | `#/arrange` | Import and organize the session |
| Mixer | `#/mixer` | Inspect and edit processing in detail |

- Navigation uses ordinary anchors, so room URLs are shareable and browser
  history works normally.
- The active link receives a dark inverted style and `aria-current="page"`.
- An unknown or empty hash falls back to Console and is normalized with
  `history.replaceState`, which does not add a history entry.
- `hashchange` updates the shell when the room changes.

### Room containers

`src/components/RoomShell.svelte` provides the shared boundary each later Phase 0
task can fill without rebuilding the shell:

- a room header with a “Room” eyebrow, an `<h1>`, and the plan’s purpose line;
- a `.room__canvas` content region that can host the meter bridge, timeline, or
  processing panel added by Tasks 0.2–0.6;
- `data-room` and an `aria-labelledby` connection for structure and testing.

Each room component (`src/rooms/*.svelte`) is a separate file and renders
`RoomPlaceholder` with a label and a note about the task that will fill it. No
detailed room layout was invented.

## Implementation decisions and rationale

**Material-risk check before replacing the site.** The npm registry was
reachable, `@sveltejs/vite-plugin-svelte` 6.2.4 explicitly supports Vite 7, the
build configuration was writable, and the old source was archived first. The
migration therefore did not risk leaving the repository unable to build, so it
was not treated as a blocking prerequisite. (The earlier blocked report in this
file described a platform that made `vite.config.ts` read-only; that restriction
does not apply in this workspace.)

1. **Svelte 5 + Vite, not React.** The plan locks Svelte + TypeScript + Vite
   (§13, §16). The temporary React site was replaced. `@sveltejs/vite-plugin-svelte`
   6.2.4 was chosen because its peer range supports the installed Vite 7 line;
   the 7.x plugin line requires Vite 8.

2. **Hash routing (`#/console`, `#/arrange`, `#/mixer`).** The plan does not
   require path-based URLs, and the shell must remain static-host friendly and
   compatible with the single-file build. A hand-written hash router avoids a
   routing dependency and preserves browser back/forward behaviour. No router
   library was added.

3. **Flat gray-box styling only.** Plan §14 defines Phase 0 as “Flat, unstyled
   gray-box layout only… before applying the vintage visual system.” No design
   tokens, vintage materials, lamp glow, or component skin were created; those
   belong to Tasks 1.1–2.x. Gray values and spacing are intentionally local to
   the shell, not a token system.

4. **One shared room boundary, separate room files.** `RoomShell` gives Tasks
   0.2–0.6 a stable outer container. Each room remains its own component so later
   tasks can replace only that room’s content without touching navigation or the
   shell.

5. **Navigation is plain anchors, not script-only buttons.** This keeps room URLs
   shareable, makes every room reachable directly, and lets the shell react to
   `hashchange` for both clicks and history navigation.

6. **Dependency changes were necessary for the mandated migration.** Removed:
   React, React DOM, `@vitejs/plugin-react`, Tailwind CSS and its Vite plugin,
   `clsx`, `tailwind-merge`, `lucide-react`, `react-markdown`, `remark-gfm`, and
   the React type packages. Added: `svelte`, `@sveltejs/vite-plugin-svelte`, and
   `svelte-check`. Plan §18 requires dependency changes to be reported; this
   section is that report.

7. **Vite patch bump 7.3.2 → 7.3.7.** `npm audit` reported high-severity
   development-server advisories against Vite 7.3.2. The patch release is
   semver-compatible with plugin 6.2.4 and removes those advisories. One low
   advisory remains in the dev-only `esbuild` transitive dependency; the
   production dependency set audits clean.

8. **No external fonts or assets.** The old Google Fonts link was removed.
   `index.html` loads no network assets and the favicon is an inline data URI,
   consistent with the plan’s offline-environment rule.

9. **No global state or project model.** Room selection is the only shared state
   and is intentionally local to the shell, as permitted by the task’s scope.
