### Track bank

- Exactly 20 track placeholders, labelled `Track 01` through `Track 20`.
- Every strip has a fixed 6 rem width (`flex: 0 0 6rem`). Strips never shrink
  to fit the available width.
- The track row uses `width: max-content` and `min-width: 100%`; its measured
  content width is 2080 px at both tested sizes.
- The scroller uses native `overflow-x: auto` with `overflow-y: hidden` and
  `overscroll-behavior-x: contain`. There is no JavaScript scrolling
  implementation.
- The track scroller is keyboard-focusable (`role="region"`, `tabindex="0"`) so
  keyboard users can reach the horizontal scroll area. Svelte's
  noninteractive-tabindex warning is suppressed with a scoped `svelte-ignore`
  for this valid scroll-container exception.

### Pinned bus/Return rail

- The rail is a separate flex column beside the track scroller, not part of the
  scrolling content. Therefore it remains fully visible while tracks scroll.
- It is positioned at the right end of the channel bank, matching plan §8a:
  "pin Return channels at the end of the Console channel bank alongside bus
  masters."
- Contents:
  - One generic `Bus master` placeholder.
  - `Reverb Return` placeholder.
  - `Delay Return` placeholder.
- The two Returns match the two default v1 Return buses in plan §8a and §16.
- The bus-master count is intentionally not fixed. The plan requires bus masters
  to be pinned/accessible but does not lock a v1 bus-master count, so one
  generic placeholder represents the reserved area.
- A dashed vertical separator and uppercase rail label make the pinned area
  structurally identifiable without Phase 1 color coding.

### Strip placeholders

Each strip contains:

- A small code/type header (`01`/`TRK`, `BUS`/`BUS`, `R1`/`RET`, etc.).
- A track, bus, or Return name.
- Neutral dashed placeholder sections labelled `Trim`, `Pan`, `Fader`,
  `Mute / Solo`, and `Peak`.

These sections reflect the structural categories named in plan §3 and the
hardware reference. They are **not** controls, meters, or inputs. No faders,
buttons, knobs, meters, or state were implemented.

### Responsive safeguard

At `max-width: 40rem`, the bank stacks the pinned rail below the track scroller
and allows the pinned row to scroll horizontally if necessary. This keeps the
mobile layout from forcing page-level horizontal overflow. It does not affect
the required 1920 px or 1024 px review widths, where the rail remains pinned at
the right.

## Deviations and interpretations

1. **Generic bus-master placeholder, not a fixed bus count.** The plan requires
   bus masters to remain accessible/pinned but does not lock a v1 bus count. One
   generic `Bus master` placeholder preserves the reserved area without
   inventing a final bus count.
2. **Pinned rail implemented as a separate flex rail rather than a CSS-sticky
   element inside one scroll container.** This guarantees that the rail remains
   entirely visible and is simpler to reason about than sticky-within-scroll.
   The visual and behavioural result matches the plan requirement.
3. **Responsive stack below 40 rem.** Added as a practical safeguard so very
   narrow layouts do not force page-level overflow. It does not change the
   required 1920 px / 1024 px pinned-right behaviour.
4. **No `decisions-log.md` was created.** The document does not exist in the
   repository. The only open product detail encountered—the exact number of bus
   masters—is recorded here and remains changeable in a later task.
5. **No bank paging controls were added.** Task 0.3 asks for the horizontal bank
   and pinned bus/Return placeholders. Paging/bank selection belongs to later
   work.
