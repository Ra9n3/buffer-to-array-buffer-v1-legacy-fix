## 2. Reverb — the proposed network

### 2.1 Shape

- **Order 8** feedback delay network, Householder feedback matrix
  `A = I − (2/N)·J` (N = 8), so `y_i = x_i − 0.25·Σx`: orthogonal, lossless, cheap
  (one shared sum per sample), and stable by construction.
- **Input diffusion:** a chain of Schroeder all-passes before the network, per
  configuration.
- **Early reflections:** a tapped feed-forward structure from the diffused input,
  per configuration (none for Plate).
- **Damping:** one one-pole low-pass inside **each** feedback path, so Tone changes
  *high-frequency decay* rather than final brightness (owner Q3).
- **Pre-delay:** one integer-sample delay line before the diffusers.

### 2.2 The three configurations (structural, not defaults)

| | **Room** | **Hall** | **Plate** |
| --- | --- | --- | --- |
| intent | compact, apparent early reflections | large, gradual buildup | fast, dense, diffuse, no identifiable reflections |
| FDN line lengths (ms) | 13.7 · 17.3 · 19.9 · 23.3 · 27.1 · 31.7 · 37.3 · 41.9 | 47.9 · 53.3 · 59.9 · 67.1 · 73.7 · 79.9 · 89.3 · 97.7 | 21.1 · 24.7 · 28.3 · 31.9 · 35.3 · 39.7 · 43.1 · 47.3 |
| input diffusers (ms × g) | 2.7 · 4.3, g 0.60 | 5.1 · 7.7 · 11.3 · 15.9, g 0.70 | 1.7 · 2.3 · 3.1 · 4.3 · 5.9 · 7.7, g 0.65 |
| early reflections (ms / gain) | 4.1 / +0.35 · 7.3 / −0.28 · 11.2 / +0.24 · 16.9 / −0.20 · 22.3 / +0.17 · 29.1 / −0.13, alternating L/R | 18.2 / +0.16 · 25.7 / −0.13 · 33.4 / +0.11 · 44.1 / −0.09 | none |
| reference damping `f0` (§2.4) | 5 000 Hz | 4 000 Hz | 6 000 Hz |

Lengths are milliseconds converted per rate with `round(ms · fs / 1000)`; at rates
other than 48 kHz the *diffusion pattern* shifts by up to half a sample per line,
which is documented rather than corrected. Each length is coprime with the others
at 48 kHz by design, so the network does not lock into a short periodic pattern.

### 2.3 Decay — RT60 at TONE FLAT

Per-line loop gain for a target RT60, with `L_i` the line length in seconds:

```
g_i = 10^(−3 · L_i / RT60)          (−60 dB of round-trip gain after RT60 seconds)
```

Decay range **0.2 – 10 s** (the approved control). Because every line is sized to
the *same* RT60, the network's modes decay together and the Schroeder curve is a
straight line in dB — which is what the ±15 % T30 test checks. The measurement is
defined in §5.

**The damping filter's DC gain is exactly 1**, so TONE darkens the tail without
changing the broadband RT60 at FLAT beyond the documented tolerance; at other Tone
settings RT60 shortens at high frequencies, as approved (Q3: no identical-RT60
requirement off FLAT).

### 2.4 Tone — the cutoff law

One exponential mapping, evaluated once per instance, per configuration:

```
f_lo = f0 / 4
f_hi = min(0.45 · fs, 4 · f0)
fc(tone) = f_lo · (f_hi / f_lo)^((tone + 10) / 20)        tone ∈ [−10, +10]
d       = exp(−2π · fc / fs)
y[n]    = (1 − d) · x[n] + d · y[n − 1]                   one-pole, DC gain 1
```

| module / config | −10 | 0 (FLAT) | +10 |
| --- | --- | --- | --- |
| Room | 1 250 Hz | 5 000 Hz | 20 000 Hz |
| Hall | 1 000 Hz | 4 000 Hz | 16 000 Hz |
| Plate | 1 500 Hz | 6 000 Hz | 21 600 Hz (0.45·fs cap) |
| Delay | 1 500 Hz | 6 000 Hz | 21 600 Hz (0.45·fs cap) |

Properties, all testable: continuous, strictly monotonic, no clipping of the knob's
top steps, **0 is a real filter** (the documented neutral reference, not
"unfiltered"), and +10 never re-introduces filtering beyond the rate cap. No boost,
no tilt, no saturation anywhere.

### 2.5 Stereo topology and scaling

- Input weightings (unit RMS, distinct per channel, so L and R excite the network
  differently and are never pre-summed):
  `wL = [+,+,+,+,−,−,−,−]/√8`, `wR = [+,−,+,−,+,−,+,−]/√8`.
  A mono input uses `wM = (wL + wR)/√2`, documented as the mono rule.
- Output weightings: `vL = [+,+,−,−,+,+,−,−]/√8`, `vR = [+,−,−,+,+,−,−,+]/√8`.
- `x_i = Σ_c w_in[c][i] · s_c` (pre-delayed, diffused input);
  `out_c = WET_SCALE · (Σ_i v_out[c][i] · z_i + early_c)`.
- **`WET_SCALE = 1.0`**, one fixed constant, not signal-dependent. No normalisation
  of any kind; the Return's fader is the level control. The report will record the
  measured peak and RMS of a unit-impulse response per configuration so the fader's
  starting point is known, and will not claim equal energy or loudness between
  characters. **No mono-compatibility claim** — the suite measures the fold-down and
  reports it.

### 2.6 Pre-delay

`round(preDelayMs · fs / 1000)` samples (0–200 ms → 0–9 600 at 48 kHz), max error
half a sample, applied before the diffusers. The test compares the response against
the same settings at zero pre-delay and requires the onset shift to be that many
samples; the report states plainly that the wet **onset is not pre-delay alone** —
the diffusers add their own short smear.

## 3. Delay — the proposed line

```
read   = line[writeIndex]                       (d samples old)
out    = read                                   first repeat: unfiltered
filter = (1 − d) · (g · read) + d · filterPrev   one-pole, DC gain 1, in the loop
write  = in + filter
```

- **Two independent lines**, one per channel: separate buffers, separate filter
  state, shared TIME / FEEDBACK / TONE. L feeds only L, R feeds only R. No
  cross-feedback, no ping-pong, no summing.
- **Timing:** `d = round(timeMs · fs / 1000)`, 20–2000 ms (960–96 000 samples at
  48 kHz), integer, no interpolation; maximum timing error half a sample. The DSP
  does **not** quantise to the console's 5 ms step — the step belongs to the knob.
- **Feedback:** `g = feedbackPercent / 100`, 0–90 %. At 0 % one delayed pass, no
  recirculation. The percentage is the feedback multiplier, not a repeat level after
  filtering.
- **Tone:** the same one-pole law and the same −10 / 0 / +10 cutoffs as §2.4
  (1 500 / 6 000 / 21 600 Hz), inside the loop, so repeats darken progressively and
  the **first** repeat is unfiltered (the filter is in the feedback return only).
- **Stability:** the loop is `g · H(z)` with `g ≤ 0.9` and `|H| ≤ 1` (one-pole with
  DC gain 1), so the loop gain never reaches unity at any frequency, for any Tone
  setting; the suite checks the extremes rather than assuming it.
- **Buffers:** sized `maxDelaySamples + 1` per channel in the constructor from the
  actual rate; no allocation in `process`.

## 4. Shared contract (both modules)

| behaviour | contract |
| --- | --- |
| Output | **wet only** — never a wet/dry mix; the dry path belongs to the track |
| Bypass | output silence, incoming samples not written into the network or lines, **state frozen**; un-bypassing resumes the tail exactly where it stopped (tested) |
| Reset | clears delay lines, FDN state, diffuser all-passes, damping state, pre-delay and the tail; after reset the same input reproduces the same output bit-for-bit |
| Parameters | taken at **construction** and validated then (the 6.1/6.2 convention, `data-model` §14.1/§15.1). No live changes in 6.3: changing Decay, Pre-delay, Tone, Time or Feedback means building a new instance. No smoothing, no crossfade, no pitch glide, no hidden reset — and no claim that a fixed integer delay is "click-free" when changed, because it is not changed |
| Latency | **0 samples** of processing latency for both modules; Delay time and Pre-delay are effect timing and are reported separately |
| Tails | `tailSeconds` getter: reverb `preDelay + 1.5 · decay`; delay `repeats · time`, `repeats = ceil(60 / (−20 · log₁₀ g))` for `g > 0`, else 1. No cutoff inside the module; Task 7.4 decides |
| Buffers | one `Float32Array` per channel, mono or stereo, in place allowed; built in the constructor from `DspOptions` |
| Sample rate | any rate at construction (48 kHz is the session's); all lengths, coefficients and buffers derive from it. A rate change means a new instance |
| Validation | non-finite throws; finite out-of-range clamps; unknown character throws; channel counts other than 1 or 2 throw — the established rules |
| Allocation | none in `process`, in either module |
| Determinism | no clock, no randomness, no browser API, nothing imported from outside `src/lib/dsp/` |

## 5. Test plan (signal-based, as Task 6.1 / 6.2)

**Reverb** — wet-only and bypass; unit-impulse response finite and bounded; **RT60
by T30 fit** of the Schroeder curve over `L² + R²`: −5 … −35 dB, `RT60 = −60/slope`,
±15 %, for each configuration at several Decay values across 0.2–10 s, at 48 kHz and
at least one other rate, at TONE FLAT, with a tail long enough to avoid truncation
bias (an unfit measurement is reported, never replaced by a friendlier method);
pre-delay as a sample-exact shift against the zero-pre-delay response; Tone
monotonicity (up ⇒ less HF attenuation, down ⇒ shorter HF decay, 0 = the documented
reference); **configuration differences at matched Decay / Pre-delay / Tone**
(early-reflection energy, buildup time, diffusion density); L-only, R-only,
identical, opposite-polarity (must not vanish), mono fold-down reported; block-split
identity, impulses immediately before and across block boundaries; state continuity;
determinism; reset; stability at Decay 10 s, Tone −10 and +10.

**Delay** — first-echo timing at 20 ms and 2000 ms, sample-exact at 48 kHz and one
other rate, across block boundaries and buffer wraps; feedback at 0 % (one repeat,
then silence) and 90 % (audible repeats, bounded); each repeat passes the filter once
more (measured spectral centroid or HF energy falls per repeat); Tone at its loop
position; independent L/R (no leakage after reset, swapping inputs swaps outputs,
identical inputs give identical outputs); repeats continue while the input is
silence; state continuity; determinism; reset; validation; stability at 2000 ms /
90 % / Tone −10 and +10.

**Shared** — wet-only output; bypass freeze/resume; reset reproducibility; parameter
validation; determinism; block partitions (one pass vs 1/7/512/mixed blocks);
multiple sample rates; finite output at parameter extremes; buffer capacity and
preparation outside the loop.
