## Channel-strip column

- **23 channels**: 20 tracks, plus Reverb Return, Delay Return, Bus master.
- Track count comes from `PLACEHOLDER_TRACK_COUNT` through a
  `createMixerTracks(count)` factory — a tunable placeholder, **not** a product
  requirement. It matches the Console and Arrange placeholder counts so all
  three rooms describe the same pretend session.
- The two Return buses are included because §8a calls them first-class
  selectable channels; the Bus master because the plan's bus/master path is part
  of the routing model.
- Each strip shows channel code, kind tag (TRK / BUS / RET), channel name, and
  neutral Trim / Pan / Fader / Mute-Solo slot placeholders.
- The column scrolls internally; the page does not grow.

placeholders. Nothing implies processing is available.

## Stubbed selection behaviour

- **Mechanism**: `let selectedId = $state(DEFAULT_MIXER_SELECTION)` — local UI
  state only, no store, no persistence, no cross-room sync.
- **Default**: the first channel (Track 01) is selected on room entry, so the
  panel is never empty on arrival and the layout relationship is immediately
  visible.
- **Empty state**: the panel also has a "No channel selected" branch for the
  case where nothing resolves. It is not reachable through the UI today,
  because the default selection always resolves to a real channel. It exists so
  the panel cannot render blank.
- **Identification update**: the panel's title and kind line
  (`Track 05` / `Standard track · processing chain placeholder`) are derived
  from the selection.
- **Accessibility**: strips are real `<button type="button">` elements with
  `aria-pressed`, so selection works by mouse, by Enter/Space, and is announced
  to assistive technology. Only one strip carries `aria-pressed="true"` at a
  time.

### Layout bug found and fixed during the task

The first implementation let the room grow to **1648 px** in a 713 px viewport,
producing page-level vertical scrolling. Cause: `.mixer-room` used
`height: 100%`, but the shell's grid row and the room canvas both had
content-driven heights, so the percentage chain never resolved to a definite
value. The page grew and the internal scrollers never engaged.

Fixed with Mixer-scoped rules in `app.css`: the shell is pinned to `100dvh`
with `overflow: hidden`, and `.room` / `.room__canvas` are given a definite
height. Verified after the fix — room is 580 px in a 713 px viewport, page
`scrollHeight` equals `innerHeight`, and the channel column scrolls internally.

The fix is scoped to `[data-active-room="mixer"]`. **Console and Arrange rules
were not changed**, and Console deliberately keeps its existing page-level
scrolling behaviour.

## Deviations, ambiguities, and decisions for owner input

1. **The panel does not branch by channel type — deliberately.**
   §8a and the §3 text say the detail panel "must render differently depending
   on channel type", and §8a says "a Return displays its effect-specific chain".
   But the Phase 0 task line specifies only a single processing-chain detail
   panel with stubbed selection, and the plan schedules this properly as
   **Task 2.9 — "Mixer chain-type-aware detail for bus and Return-bus channels"**.
   Implementing branching now would exceed the Task 0.5 scope and pre-empt a
   Phase 2 task.
   **This is the one point where the prompt and plan could be read as pulling in
   different directions, so it is flagged rather than decided silently.** If you
   want bus/Return channels to show a visibly different placeholder set now,
   that is a small change — say so and I will add it.
2. **23 channels rather than 20.** The plan does not specify a Mixer count.
   20 tracks plus the two §8a Return buses and the Bus master were included so
   the column demonstrates a multi-kind channel list, which is what later
   chain-aware work will need. Track count remains configurable.
3. **Empty-selection state is present but unreachable.** The default selection
   always resolves. Kept as a defensive branch so the panel cannot render blank;
   say if you would prefer a true empty state on room entry.
4. **Mixer shell pinning is new shared-shell behaviour.** It is scoped to the
   Mixer room and does not alter Console or Arrange, but it does mean Console
   and Mixer now differ in their page-scroll model. That difference is
   intentional: Console has a fixed transport designed to be revealed by page
   scroll, and the Mixer has none.
5. **Room header kept and compacted**, not hidden. Unlike Arrange, the Mixer's
   header was not marked for removal, so it remains a single compact line.

### Decision 1 — Channel-type-aware detail panels deferred to Task 2.9

**Decided:** defer chain-type-aware detail panels to the planned Task 2.9. Do
not add branching behaviour and do not pre-empt that task. The current neutral
placeholder detail layout stays in place for **all** channel types.

**Confirmed state:** the detail panel renders one neutral placeholder set
regardless of channel kind. `check:mixer` enforces this — the guard
"detail panel does not branch by channel type yet (deferred to Task 2.9)" fails
the build if a `selected.kind` conditional is introduced into the room.

**Consequence:** selecting Reverb Return, Delay Return or Bus master changes the
panel's identification (code, name, and kind line) but not its placeholder
regions. That is the intended behaviour for Phase 0 and is unchanged.

This closes deviation 1.

### Decision 2 — 23 selectable channels kept, count stays configurable

**Decided:** keep the 23 selectable channels — 20 tracks, Reverb Return, Delay
Return, Bus master. Treat the count as configurable, not a permanent product
requirement.

**Confirmed state:** the track count flows from `PLACEHOLDER_TRACK_COUNT`
through the `createMixerTracks(count)` factory; nothing in
`MixerRoom.svelte` hard-codes a channel count. `check:mixer` enforces both
guards ("track channels are built by a factory, not a markup literal" and
"MixerRoom does not hard-code a channel count"). The two Return buses and the
Bus master are declared separately in `MIXER_AUX_CHANNELS` because their
inclusion is justified by plan §8a rather than by the placeholder count.

This closes deviation 2.
