## Rotation: the whole assembly, not the pointer

```
assemblyRotation = angle + ARTWORK_ORIENTATION − ORIENTATION_TRIM
                 = angle − 88 − 2
                 = angle − 90
```

* `angle` is unchanged: `START_ANGLE −135 + SWEEP 270 × fraction`.
* The **entire** supplied `rotating-surfaces` group — both ridge rings **and**
  the index bar, in the artwork's own nesting — carries one `rotate(...)`.
  The pointer is never lifted out of that group.
* `−88` is the artwork's orientation pose, preserved as
  `ARTWORK_ORIENTATION = -88`; it is an offset on top of the value angle, never
  a replacement for the mapping.
* `ORIENTATION_TRIM = 2` is not a fudge. The supplied index bar lies along +x,
  so `rotate(−88)` leaves it 2° clockwise of 12 o'clock. With the trim the bar
  sits exactly on the graduations at every value: at minimum the assembly reads
  `rotate(-225 200 200)`, at maximum `rotate(45 200 200)`, i.e. exactly −135° →
  +135° of travel. Set `ORIENTATION_TRIM = 0` to see the artwork's literal pose
  (the index would then sit 2° past every graduation).
* The body, side wall and face circles are radially symmetric, so their
  participation is a visual no-op — they are not left "stationary while the
  pointer moves"; there is one rotating assembly.
* The environmental lighting (`data-part="fixed-lighting"`) stays fixed, as the
  brief permits: it is the panel's key light, not a property of the knob.
  **Flagged:** the per-ridge opacity ramp is baked into the rotating group, so
  the ridge brightness variation travels with the knob. That is physical
  surface lighting and it is what the supplied artwork describes.

## Minimal changes to the supplied artwork (all reported, none cosmetic)

1. **Colours are tokens.** Body, side wall, both ridge rings and the index bar
   now derive from the family (table above). Required by the brief.
2. **Recess shadow flood `#0e2646` → `black`.** The supplied flood is a dark
   blue; on an amber or green knob that reads as a leftover blue shadow.
3. **Face light arc `#7ca1d4` → family `hi`.** Same reason, in the highlight.
4. **Ridge colour variation re-expressed as opacity.** The supplied file
   listed 96 slightly different stroke colours per ring; per-ridge opacity
   against the key light keeps the same variation while letting one family
   token drive the hue. Geometry, pitch, weights, caps and count are unchanged.
5. **Explicit filter regions** on the inset / soft-light / wall-light / satin
   filters (`x/y/width/height`). Vite's SVG output and the group bounds otherwise
   clip a blur at the canvas edge; the regions match or exceed the SVG default
   (−10%…120%), so nothing that was visible before is cut.
6. **Contact shadow added** (`<ellipse cx=200 cy=336 rx=122 ry=16>`, panel-dark,
   reusing the supplied 7-unit blur filter). The artwork was drawn without a cast
   shadow; without one the knob reads as pasted onto the panel rather than
   sitting in it. This is a new element, not a change to a supplied one — remove
   it and nothing else changes.
7. **Satin group wraps side wall + body + recessed face**, in the supplied
   order, with the supplied silhouette clip; the face keeps its nested inset
   filter.
8. **Review round 2 additions** (owner-approved after the critical review
   below): rescaled panel print, a `-face-paint` gradient + deeper inset + inner
   lip so the recess reads, `--kn-ridge-dark` mixed toward black for the pale
   families, and a hover rest state. All listed with measurements in the review
   section at the end of this report.
9. **Focus ring recoloured.** The earlier component drew it in
   `--al-text-engraved` (#16150f) because it sat on the raised plastic. It now
   sits on the dark panel, where that colour is invisible; it uses
   `--al-text-primary` on a panel-coloured break at r 136.5 (between the body's
   drawn radius 132 and the first tick at 142).

## Limitations and open points

1. **The artwork source is a transcription, not a byte-for-byte paste.** The
   file the owner supplied was pasted into the conversation, not left on disk,
   so the component was written from the recorded inventory of that file — every
   geometry value, gradient coordinate, stop order, filter parameter, ridge
   count, pitch and stroke weight listed above is the supplied one, but the HTML
   structure is mine. **The owner should diff the rendered knob against the
   original SVG**; if any wrapper or unused def was dropped that the owner wants
   back, it is a small edit inside `<svg>`, not a rebuild.
2. **`color-mix()` is used** for two derived tones (deep side wall, light-ridge
   tint, ink far stop). Chromium/WebKit/Firefox current all support it; the
   fallback in a pre-2023 browser would be an unset value on those three stops.
   If that matters, the alternative is six more tokens, which the task's scope
   lock forbids.
3. **The index bar is not white in the cream variant.** Cream's ink is
   `#241f18`; a white bar on a near-white body would be illegible. This is the
   one deviation from "separate white pointer" and it is colour-mechanism
   driven, not a redesign.
4. **Per-ridge brightness rotates with the knob** (physical surface lighting,
   permitted). The panel's arc/ellipse highlights stay fixed. If the owner
   prefers the ridges to keep a fixed light, the ramp is one `stroke-opacity`
   expression.
5. **The 2° orientation trim** is explained above. It exists only so the index
   agrees with the graduations; `ORIENTATION_TRIM = 0` restores the literal
   supplied pose.
6. **Playground route is still `#/dev/components`** — the app defaults to
   `#/console`, and the hash is a locked Phase 0 decision, so the knob section
   is reached by the hash, as before.
7. Still open from earlier rounds, untouched here: the exposed PAT should be
   rotated; amber/orange token retune (D1.2.10); the orphaned `1.01`/`1.02`
   reports; the missing §19 in the spec; whether the 16–20 flute figure may be
   overridden by photographs (now moot — this artwork's ridge ring is the
   96-ridge supplied one).

### Material changes

1. **A declared nickel ramp** (`--kn-nickel-*`, seven tones, one place):
   `#c2c6c9` → `#8f9498` → `#6e7377` → `#4f5357` → `#2f3336`, plus a groove
   `#34383b` and a crest `#c3c7cb`. Every channel sits within 8 points of the
   others, so the metal is neutral — no warm yellow cast, no blue cast.
2. **Body and side wall repainted** with that ramp on the *existing* gradient
   geometry (same axes, same stop offsets, same 85,65 → 310,335 and
   55,95 → 325,360 userSpaceOnUse axes).
3. **Ridge rings repainted as metal**: grooves in `--kn-nickel-groove`, crests
   in `--kn-nickel-crest`, on the same 96 + 96 lines with the same pitch,
   weights (2.2 / 1.4), round caps and per-ridge opacity ramp — the ramp's
   range was re-tuned (grooves 0.82–0.96, crests 0.26–0.64) so recesses stay
   dark and the crests read as machined highlights rather than white teeth.
4. **One added specular strip** on the rim (`-rim-light`, r 148.6, stroke 2.2):
   the turned edge catching the room light, bright on the lit side, dark on the
   far side. This is the only new gradient.
5. **One added contact shadow** where the cap seats into the metal
   (`knob__cap-seat`, r 132.6, blurred), so the nickel reads as a machined
   collar the cap sits into rather than a flat disc behind it.
6. **Satin grain raised** from 0.045 to 0.075 alpha on the supplied
   `feTurbulence`/`feColorMatrix` chain — still the same filter, one parameter.
   At 0.045 the grain was invisible, and "brushed, not mirror-polished" needs
   some texture. The grain is isotropic on purpose: an anisotropic streak filter
   would have to live on the body, which does not rotate, while the ridges do —
   the streaks would then contradict the turning knurl.
7. **Cap step adjusted 84 % → 94 %** of the family colour (still mixed toward
   black, still derived from the same `--cap-*` tokens). With the metal now
   providing the step into the recess, the cap no longer needs to be darkened
   as heavily to sit down, and the six colours read truer. Token values were not
   changed; this is a shading mix, not a new palette. **This is the one place
   the cap's appearance moved — say the word and it goes back to 84 %.**

## Review round 4 — the cap must sit *inside* the grip

**Status: checkpointed at the owner's request, in the commit that carries
this report. No tag, no approval recorded.**

The owner reviewed the brushed-nickel build and marked one defect: on the
**lower-right** the cap read as sitting *above* the grip, and on the
**upper-left** as sunk *into* it. The cap was not being contained by the collar.
The instruction was explicit — do not change the knob's shape, only make the cap
read as seated inside the grip, contained by it.

### Diagnosis

The saved artwork's inset "recess" shadow was an **offset shadow**: the supplied
`feOffset` plus the deepening from review round 2 put the shadow band down and
right of the cap (`dx 4.5 dy 8.5`). That is the physics of a *drop* shadow, not
of a recess. Consequences, both visible in the owner's markup:

* **lower-right** — a dark band between the cap edge and the knurl, i.e. the cap
  looks like a loose plate lying on the metal, lifted on that side;
* **upper-left** — the offset leaves *no* shadow at all against that edge, so the
  cap's own paint ran straight into the ridge band and looked sunk on that side.

The one other contributor was the face highlight arc, which lifted the cap's
upper-left edge and re-inforced the "sunk here, floating there" read.

### What changed (shading only — no geometry touched)

1. **The recess shadow is now symmetric.** `feOffset dx="0" dy="0"`,
   `stdDeviation 4.2`, flood `0.8`. The supplied filter structure
   (offset → blur → composite out → flood → merge) is untouched; only the offset
   became zero, so the shadow rings the cap evenly the way a collar gripping a
   cap casts it.
2. **A shadow across the cap's face from the collar's far wall** —
   `-cap-wall-shade`, a linear black overlay from the upper-left at 0.3 opacity
   fading to nothing by the middle. This is what puts the cap physically *down
   inside* the grip instead of level with it.
3. **The face falls away into the recess all round** — `-cap-inset`, a radial
   black overlay from transparent at 62 % to 0.42 at the rim. Both overlays are
   clipped to the supplied `-face-clip`, so nothing spills past r 131.
4. **The seat ring is stronger** — `knob__cap-seat` opacity 0.34 → 0.42, stroke
   5 → 6, still on the machined annulus at r 132.6.
5. **The inner specular arc was calmed** — the fixed-lighting arc that crosses the
   face went from 0.3 to 0.16 opacity, so it no longer lifts the cap's upper-left
   edge against the collar.

**Geometry lock holds.** No `r`, `cx`, `cy`, `d`, `viewBox`, transform, ring
count, pitch or pointer attribute changed in this round; the diff adds only the
two shading gradients, one clip group and two overlay circles that reuse the
existing r 131 disc. `check:knob` now asserts the symmetric offset, the
containment overlays, and that the cap disc is still r 131 at (200,200).
