## Home and the project lifecycle (as built; `data-model.md` §11)

### What Home lists, and where it comes from

The *Recent projects* panel is `lifecycle.recent()`: the entries of
`alloy.projects` (schema `alloy.projects/1`, `{ id, name, template,
openedAt }`, newest first, capped at 12) **each judged against its own
stored copy at render time** — `alloy.project.<id>` is read and parsed every
time the list renders, so the list reflects what is actually in storage
now, not what the index remembers. An entry whose manifest is unreadable,
missing, belongs to another id, names a template this build cannot rebuild,
or rebuilds into an invalid routing graph is shown as **Unavailable — <the
reason>** with **no Open key**; it is never presented as reopenable and
nothing is fabricated for it. A malformed index entry (e.g. a numeric name)
is dropped by the parser; an index that is not an index yields an empty
list. The empty list prints "No recent projects yet."; without storage it
prints "Storage is not available in this browser, so recent projects cannot
be kept." No `localStorage` access happens outside the adapter the shell
injects — the lifecycle takes storage, a clock and an id source as
arguments (tests use maps and counters).

### What can and cannot be reopened

| entry | can it reopen? | why |
| --- | --- | --- |
| the fixture session (`session-fixture`), edited or pristine | **yes** — as the approved 20-track fixture with its saved values applied (1 076 fields) | template `session-fixture` under its one id |
| a Task 3.3 manifest of the fixture session (no `template` field) | **yes** | a template-less manifest of the fixture's id is treated as the fixture |
| a project started empty (`project-<uuid>`, template `empty`) | **yes** — as Master only (it has no fields) | template `empty` under any id |
| a saved copy with a damaged / foreign / unknown-template manifest | **no** — printed as unavailable with the reason | it cannot be rebuilt truthfully |
| a saved copy whose values would break the routing rules | **no** — `invalid` with the rule's message | `validateGraph` refuses it; the current project is untouched |
| any project with its own channel structure (an imported project) | **not in this build** | the manifest holds identity and field values, not channels (3.3, D3.3.3); that is Phase 5's import — documented, not invented |

A value that fails its field's validation (type / range / reference /
family rule) keeps the template's value and is reported in `skipped`; the
next autosave writes the corrected manifest. In the browser evidence the
reopened fixture applied all 1 076 values with `skipped: []`.

### Start empty

`lifecycle.startEmpty()` draws a fresh id from the shell
(`crypto.randomUUID`, re-drawn if already listed), builds the empty project
(owner: **Master only**), writes its manifest at once under
`alloy.project.<id>` so that its entry is reopenable, flushes the outgoing
project (and gives a never-edited one its first copy — `ensureStored`),
then `loadProject` → `autosave.retarget` → index touch. The three rooms
render `EmptyProjectNotice` instead of their channel UI: "“Untitled
project” has no tracks, Returns or buses yet — <what the room would show>.
Stem import arrives with the audio engine (Phase 5)." with a link back to
Home. Without storage the project still opens and Home says, in the warn
tone, that it could not be saved.

### Restore at start, and the dev fixture workflow

`installProjectShell` now runs **before** mount and ends with
`lifecycle.restoreLast()`: the newest listed project comes back when its
copy is valid; otherwise the store keeps the fixture session it booted
with, and the result (`{ outcome, id, because | skipped }`) is on
`window.alloy.restored` under `?debug`. Either way the open project is
recorded in the index and given its first copy. So a **fresh browser boots
the pristine fixture exactly as before** (route `#/` → Home, the fixture
"Open now", one entry), and after starting empty the fixture is one Open
key away. This is the owner's reversal of the 3.3 rule "autosave never
restores on load" — see D4.1.1.

### Identity

`project.id`, `name` and the new `template` travel together through the
manifest, the index, `loadProject` and `autosave.retarget`; a reopened
project is the project that was saved (same id, same key, history empty,
autosave clean against the text it was reopened from). The manifest schema
is unchanged (`alloy.project-manifest/1`; `template` is additive and
optional on read).

## First-run guidance (as built)

- **Where / when:** the first panel of Home, while `settings.onboarding ===
  "pending"` — on a fresh browser, and again after Settings → "Show again".
  Four lines of the essential workflow stated as this build has it: *Start*
  (reopen or start empty here), *Import* (into Arrange — import itself
  arrives with the audio engine), *Mix* (MIX in the Console — arrives with
  the engine), *Inspect* (the Mixer's detail; undo with Ctrl / Cmd + Z).
- **Skip / finish:** two momentary keys, **Skip** (`skipped`) and **Done**
  (`done`); either removes the panel at once. Both are written to
  `alloy.settings`, so a reload does not show it again (measured: after
  Done + reload, `guide: false`, document `onboarding: "done"`).
- **Non-blocking by construction:** it is a panel among the others — no
  `dialog`, `aria-modal`, `inert`, focus trap, overlay or timer anywhere in
  `src/screens` (guarded); the header tabs and the Settings link sit before
  it in the Tab order; every room is reachable while it is on screen.
- **Without storage:** it shows each visit (nothing can be remembered) and
  says nothing about it.

## Key decisions and rationale (`decisions-log.md` D4.1.1–D4.1.9)

- **D4.1.1 (owner)** — Reopen = the template under the saved identity + the
  saved values; the last project is restored at start (fallback: the
  pristine fixture). The 3.3 write side is unchanged; the loader validates
  every value and the whole graph before the store takes anything.
- **D4.1.2 (owner)** — The empty project is Master only; every room shows an
  explicit empty state. The plan's default Returns are not invented.
- **D4.1.3 (owner)** — Home `#/`, Settings `#/settings`, neither a room; the
  wordmark is the way Home; unrecognised hashes land on Home. Builder's
  choice within it: start-empty offers Arrange, reopen offers Console; Home
  never navigates by itself.
- **D4.1.4** — The guide is one Home panel, remembered as `onboarding`;
  never a modal.
- **D4.1.5** — Reduced motion = a stored preference mirrored onto `<html
  data-motion>`, reducing everything on top of the system query.
- **D4.1.6 (owner + builder)** — Settings carry the plan's items only; export
  = WAV as a printed fact + the three output types; the folder is chosen at
  export time; profile intents printed without numbers.
- **D4.1.7** — The lifecycle is pure of the browser and judges entries
  against storage at every render; `ensureStored` gives an unedited project
  its first copy; switch order flush → load → retarget → touch.
- **D4.1.8** — `loadProject`, `history.rebind`, `autosave.retarget`,
  `project.isEmpty` are additive and backward-compatible; the settings
  store mirrors the project store's pattern.
- **D4.1.9** — Home / Settings are built from the approved parts; the rooms'
  grey band (`app.css`, pinned) is mirrored for the screen header and the
  status readout — the one hex exception in `src/screens`, guarded.
