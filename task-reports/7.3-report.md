## 1. What was implemented

ALLOY now has an engine-only masking-resolution layer in `src/lib/engine/masking.ts`.
It detects meaningful frequency-and-time conflicts, protects the higher-Priority
contributor, resolves persistent conflicts with static EQ, intermittent conflicts with
external-key Dynamic EQ, addresses wet reverb/delay tails through the existing
post-fader send architecture, re-measures after EQ, and escalates to external-key
compression only when meaningful conflict remains.

The layer is deterministic and explainable. It introduces no AI/ML, no dependency, no
new DSP algorithm, no new routing edge kind, no Return sidechain destination, no UI,
no store/persistence wiring, no transport/playback change, no export work, and no
Task 7.4 bounded-chunk rendering orchestration.

## 3. Detection methodology

`measureMaskingSources` runs the existing engine in blocks and measures:

- **dry sources**: each track's post-fader output tap, gated by Task 7.1 audibility;
- **wet sources**: each active post-fader send, attributed to its sending track as
  `trackId>returnId`. The send signal is passed through the same approved
  `ReturnChain` settings in isolation. Because the Return effects are linear and
  static during a render, this is superposition, not a new effect or routing model.

The measurement includes `tailSeconds` of silence after the last input so wet tails
participate. A wet source inherits the sending track's Priority. A Return Bus is not
treated as an ordinary track.

`detectMaskingConflicts` requires all of:

1. different contributing tracks;
2. a higher-Priority protected source and a lower-Priority yielding source;
3. simultaneous band energy above `energyFloorDb`;
4. band salience (`minBandShare`) so ordinary low-level spectral overlap is not cut;
5. relative level within `maskingWindowDb`;
6. enough conflict cells to be meaningful.

Contiguous conflict cells become time intervals. Persistent conflicts occupy at least
`persistentRatio` of the longer active run and `persistentMinCells`; otherwise a
sufficiently long conflict is intermittent. Equal Priority is not arbitrarily cut.

Each conflict identifies the protected/yielding sources, affected band, intervals,
active/conflict cell counts, mean band levels, excess dB and Priority difference.

## 4. Resolution methodology

`resolveMaskingConflicts` clones the project and writes only Auto parameters:

- **persistent dry conflict** → proportional static EQ cut on the lower-priority track;
- **intermittent dry conflict** → engine-owned Dynamic EQ dip keyed by the protected
  track through the existing sidechain path;
- **wet conflict** → proportional send reduction on the lower-priority sending track.
  Persistent wet conflicts use the full requested cut; intermittent wet conflicts
  scale by measured duty cycle because a Return has no dynamics to key.

Manual EQ gain/frequency/Q, Manual sends and Manual compressor parameters are never
written. Existing configured `dynamicDepthDb` values are preserved. The masking
Dynamic EQ overlay is additive only on bands whose depth is `null`. When a band already
has a configured depth, masking may add the external key but cannot resize the depth;
the action and ledger report that **effective** configured depth, not the requested cut.
If the configured depth is below the minimum useful cut or above the remaining masking
cut budget, masking skips the key rather than resizing the depth or exceeding the budget.

Conflicts are resolved deterministically in Priority order. A cumulative ledger tracks
masking-applied EQ reduction per track/band and send reduction per Return. The default
cumulative EQ safety limit is 6 dB per track, configurable and carried across reruns.

`resolveMaskingAudio` re-measures after EQ. Compressor escalation is considered only
for conflicts that received an EQ move and still have meaningful remaining excess. It
adds an external-key compressor edge and may lower an Auto threshold / raise an Auto
ratio. A bypassed compressor or an existing compressor key is not overridden. A final
measurement reports remaining conflicts.

## 6. Numerical defaults introduced and rationale

No universal masking threshold or genre rule is claimed. The defaults are conservative,
configurable starting points that reuse the 5.2 grid and 6.x ranges:

| Default | Value | Rationale |
| --- | ---: | --- |
| `energyFloorDb` | −60 dB | near-silence gate, aligned with the analysis near-silent convention |
| `minBandShare` | 0.05 | a band must be musically salient, not incidental spectral leakage |
| `maskingWindowDb` | 12 dB | avoid cutting a source already far below the protected source |
| `persistentRatio` | 0.6 | majority of the longer active run |
| `persistentMinCells` | 3 | at least 300 ms on the 100 ms grid |
| `intermittentMinCells` | 2 | at least 200 ms, not a single-cell accident |
| `targetSeparationDb` | 3 dB | modest protected-source headroom |
| `maxCutPerConflictDb` | 3 dB | proportional, not aggressive |
| `minCutDb` | 0.25 dB | avoid meaningless micro-writes |
| `cumulativeCutLimitDb` | 6 dB | conservative anti-hollowing safety limit |
| `maxSendCutDb` | 6 dB | bounded wet send reduction |
| `escalationThresholdDb` | 1.5 dB | compression only for meaningful remaining conflict |
| `maxCompThresholdShiftDb` | 6 dB | bounded compressor escalation |

All are recorded in `decisions-log.md` D7.3.1 and remain tunable.

## 9. Deviations from the specification and why

1. **Dynamic EQ depth ownership.** The existing `dynamicDepthDb` has no Auto/Manual
   mode. Rather than silently overwrite it or add a new persisted/UI model field
   outside this engine task, masking uses an additive engine-owned overlay only where
   the configured depth is null. Existing configured depths are preserved. Focused
   verification confirmed that a configured depth caps the intermittent dip; the
   action/ledger now report the effective configured depth instead of the requested
   cut. Required extra attenuation beyond that depth is not invented: only
   re-measurement + compressor escalation remains (persistent conflicts can also use
   static EQ).
2. **Intermittent wet conflicts.** A Return Bus has no compressor/Dynamic EQ and cannot
   be a sidechain destination under Task 7.2. The layer therefore reduces the
   lower-priority Auto send proportionally to measured duty cycle instead of inventing
   Return dynamics. Persistent wet conflicts use the full proportional send cut.
3. **Wet attribution cost.** A shared Return output cannot identify which send produced
   a tail. The measurement pass therefore runs the same approved ReturnChain per active
   send in isolation (linear superposition). This reuses the existing DSP and is
   necessary for explainable per-track wet attribution.

### 11.1 Dynamic EQ depth ownership

**Question.** What happens when a masking conflict hits a band whose
`dynamicDepthDb` is already configured, and can masking still achieve the required
extra attenuation without overwriting that depth?

**Finding.** The overlay law in `chains.ts` is
`band.dynamicDepthDb ?? overlay?.depthDb ?? null`: a configured depth always wins and
masking never replaces it. On an intermittent conflict the resolver therefore adds the
external sidechain key but **no overlay** when the band already has a depth. Dynamic EQ
then applies the configured depth while keyed, so the attainable dip is capped at that
configured depth, not at the requested masking cut. If the conflict remains, the only
remaining automatic path is re-measurement followed by compressor escalation; that path
is skipped when the compressor is bypassed. A *persistent* conflict on the same band is
different: it can still add an independent static EQ gain cut without touching the
configured dynamic depth.

**Focused correction.** The action and ledger previously credited the *requested* depth
even when a configured depth capped it. They now credit the **effective** depth
(`configuredDepthDb ?? requestedDepth`) and the reason states the configured depth and
the request. This is a reporting/safety correction only: no configured depth is overwritten and no
DSP algorithm changed. A configured depth outside the remaining masking cut budget is
skipped (key not added) rather than resized.

**Objective test.** `tests/masking.test.mjs` — “focused: a configured dynamicDepthDb is
preserved and caps the masking dip”. A 1 kHz intermittent protected key against a
continuous lower-priority tone, with `lmf.dynamicDepthDb = 1` and a 3 dB request:

- configured depth remains `1`; no masking overlay is added to that band;
- action `cutDb = 1`, reason `configured 1.00 dB depth (requested 3.00 dB; depth preserved)`;
- ledger credits 1 dB, not 3 dB;
- measured keyed dip on the yielding track tap: **−0.994 dB** (≈ the configured 1 dB);
- with the compressor bypassed, the final conflict remains (excess ≈ **7.11 dB**),
  confirming masking did not fabricate the missing attenuation.

A second focused test confirms a persistent conflict on a configured dynamic band still
applies a static EQ cut while preserving `dynamicDepthDb = 2`.

### 11.2 Wet-source attribution / Return linearity

**Question.** Does processing each send through the Return chain in isolation accurately
represent its contribution to the combined Return output?

**Finding against the actual DSP.** At fixed settings both Return effects are linear and
time-invariant, so waveform superposition holds:

- `dsp/reverb.ts`: FDN order 8 with an orthogonal Householder mix, per-line constant
  loop gain, one-pole damping inside the loop, integer pre-delay, feed-forward early
  taps, wet-only output, `REVERB_WET_SCALE = 1`, explicitly no signal-dependent
  normalisation or make-up gain. Bypass outputs silence.
- `dsp/delay.ts`: one integer delay line per channel, constant feedback, one-pole damping
  in the loop, wet-only output, `DELAY_WET_SCALE = 1`, no normalisation, make-up gain,
  saturation or modulation. Bypass outputs silence.
- `ReturnChain` applies the effect then a constant Return level. No signal-dependent
  stage sits between the summed sends and the Return output.

Therefore `R(Σ gᵢ·xᵢ) = Σ R(gᵢ·xᵢ)` for the waveform. The small residual is Float32
rounding/order, not a model error. **Important distinction:** per-band *powers* of
correlated contributions are not additive even though waveforms superpose; masking
measures each isolated source and compares sources, it does not sum isolated band powers
to reconstruct the combined Return spectrum.

**Objective comparison test.** `tests/masking.test.mjs` — “focused: isolated per-send
ReturnChain output sums to the combined Return output (reverb + delay)”. Two senders at
different send levels feed one Return; the combined Return tap is compared sample-by-sample
against the sum of isolated per-send `ReturnChain` outputs (including the silent tail).
Tolerances: max sample error < 1e-6, tail error < 1e-6, relative RMS < 1e-6 (< −120 dB).

| Return | Max sample error | Relative RMS | Error (dB) |
| --- | ---: | ---: | ---: |
| reverb / room | 2.98e-8 | 4.83e-8 | −146.4 |
| reverb / hall | 2.98e-8 | 4.64e-8 | −146.6 |
| reverb / plate | 2.24e-8 | 4.66e-8 | −146.6 |
| delay / digital | 3.73e-8 | 4.41e-8 | −147.2 |

All four cases pass, including the tail region after the dry inputs stop.
