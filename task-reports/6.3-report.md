## 2. Summary

- **Reverb** — one algorithmic feedback-delay network, order 8, Householder
  feedback matrix, in three structurally distinct configurations (Room · Hall ·
  Plate). DECAY is a broadband RT60 target at TONE FLAT; PRE-DELAY is a separate
  integer ring before the diffusers; TONE is a one-pole low-pass **inside every
  feedback path**; the output is wet only at one fixed scale.
- **Delay** — one line per channel, integer-sample time, linear feedback that leaves
  the **first repeat unfiltered at unity**, TONE inside the loop only, no
  cross-feedback, no ping-pong, no input summing, no tape processing.
- Both: state across blocks, deterministic, no allocation in `process`, zero
  reported latency, wet-only, bypass that freezes state, `reset()`, a documented
  tail contract, and the project's validation conventions (non-finite throws, finite
  out-of-range clamps).

## 4. Implementation summary

### 4.1 The reverb network

One network, shared by the three configurations:

- **Order 8, Householder feedback** `A = I − (2/N)·J`, i.e. `y_i = x_i − 0.25·Σx`.
  Orthogonal: the matrix neither gains nor loses energy, so stability is structural
  and the decay is set by the line gains alone.
- **Line gains** `g_i = 10^(−3·L_i/(RT60·CALIBRATION))`, `L_i` in seconds — the
  loop gain that reaches −60 dB after RT60. `CALIBRATION = 1.315` (§5.1).
- **Pre-delay** — an integer ring of exactly `round(ms·fs/1000)` samples **before**
  the diffusers. The suite proves the whole wet signal is the un-delayed render
  shifted by exactly that many samples, with nothing before it.
- **Input diffusion** — a Schroeder all-pass chain per channel, distinct per
  configuration (2 / 4 / 6 stages at 0.60 / 0.70 / 0.65).
- **Early reflections** — feed-forward taps read from a power-of-two history of the
  diffused signal; Room 6 taps, Hall 4, Plate none.
- **Output** — four ÷√8 weightings
  (`wL=[+,+,+,+,−,−,−,−]`, `wR=[+,−,+,−,+,−,+,−]`, `vL=[+,+,−,−,+,+,−,−]`,
  `vR=[+,−,−,+,+,−,−,+]`; mono `wM=vM=(wL+wR)/√2`). L and R excite the same network
  through **different** input weightings; L+R is never pre-summed.
- `REVERB_WET_SCALE = 1`; wet only; no signal-dependent normalisation.

### 4.2 The three configurations (PROVISIONAL, approved)

| | lines (ms) | diffusers | early reflections (ms) | TONE f0 |
| --- | --- | --- | --- | --- |
| Room | 13.7, 17.3, 19.9, 23.3, 27.1, 31.7, 37.3, 41.9 | 2 @ 0.60: 2.7, 4.3 | 6 taps 4.1–29.1, alternating channel | 5 kHz |
| Hall | 47.9, 53.3, 59.9, 67.1, 73.7, 79.9, 89.3, 97.7 | 4 @ 0.70: 5.1, 7.7, 11.3, 15.9 | 4 taps 18.2–44.1 | 4 kHz |
| Plate | 21.1, 24.7, 28.3, 31.9, 35.3, 39.7, 43.1, 47.3 | 6 @ 0.65: 1.7–7.7 | none | 6 kHz |

They differ structurally — spacing, build-up and early reflections — and the suite
asserts all three differences plus that the same settings produce different tails.
These are algorithmic, character-inspired configurations: no hardware emulation, no
impulse response, no claim of an exact room.

### 4.3 TONE — damping inside the loops

```
f_lo = f0 / 4        f_hi = min(0.45·fs, 4·f0)
fc(tone) = f_lo · (f_hi/f_lo)^((tone + 10)/20)
d = e^(−2π·fc/fs)    y[n] = (1 − d)·x[n] + d·y[n − 1]      (DC gain 1)
```

- Placed **inside** the reverb's eight feedback paths and **inside** the delay loop —
  never on the wet output, never as "0 = unfiltered".
- FLAT (0) is the geometric centre of the range and a real filter: the neutral
  reference. The suite checks the endpoints, the geometric centre, monotonicity in
  TONE, and that the delay's first repeat is bit-identical at every TONE setting.
- Endpoints: Room 1 250 / 20 000 Hz, Hall 1 000 / 16 000 Hz, Plate and Delay
  1 500 / 21 600 Hz at 48 kHz.

### 4.4 The delay

- **Time** `round(ms·fs/1000)` whole samples; no fractional interpolation; the
  suite asserts exact timing at 44.1 / 48 / 96 kHz for 20, 137, 500 and 2 000 ms.
- **Feedback** `g = percent/100`, loop `write = in + LP(g·read)` with the read taken
  before the write, so the output is the line itself: the **first repeat is the
  input, unfiltered and at unity**, and at 0 % there is exactly one repeat.
- **No cross-feedback**: a left-only impulse leaves the right channel silent
  (asserted to exactly 0), and unequal channel content stays unequal.
- **Stability**: DC gain 1 with `g ≤ 0.9` bounds a constant input at `1/(1−g)`; the
  suite checks the 90 % case over ten seconds, and that the tail decays after the
  input stops.

## 5. Important DSP decisions and rationale

### 5.1 The decay calibration (one constant, not a tolerance)

The approved law targets an **undamped** network. The damping filter in the loop
takes a further, frequency-dependent slice of every pass, so a broadband T30 fit of
the damped engine reads **short** of the knob — uncalibrated it measured −14 … −24 %.
`REVERB_DECAY_CALIBRATION` scales the RT60 used to compute the line gains so the
measured T30 lands on the knob. It is a single documented constant; **the ±15 %
acceptance was not widened and the measurement method was not changed.**

Choosing the value was a measured decision, not a guess. The residual error spans
about 29 % from the shortest/highest-rate corner to the longest-decay corner, so the
constant has to be centred rather than biased to one end: 1.30 leaves Hall @ 96 kHz /
0.5 s at −15.2 %, 1.32 leaves Plate 10 s at +15.0 %, and **1.315** puts the grid at
−14.6 % … +14.5 %. Two corners therefore sit close to the boundary, which is stated
rather than hidden.

### 5.2 What DECAY measures — and the two limits at short decays

Broadband T30 at TONE FLAT, fitted −5 … −35 dB by Schroeder backward integration of
L²+R². Measured deviations with the shipped constant:

| character | 0.5 s (44.1 / 48 / 96 kHz) | 1.5 s | 4 s | 10 s |
| --- | --- | --- | --- | --- |
| Room | +3.2 / +1.7 / −4.5 % | +8.0 / +7.7 / +5.0 % | +9.6 / +9.6 / +7.4 % | +10.2 / +10.0 / +8.1 % |
| Hall | −3.3 / −4.3 / **−14.6** % | +4.1 / +3.4 / −4.2 % | +9.7 / +9.5 / +6.4 % | +11.7 / +11.9 / +10.0 % |
| Plate | +4.6 / +4.2 / −1.7 % | +11.1 / +11.1 / +8.4 % | +13.1 / +12.9 / +11.3 % | **+14.5** / +14.5 / +13.2 % |

Every cell of 0.5–10 s at all three rates is inside ±15 %, and the suite asserts
that grid (Room/Hall/Plate at 0.5, 1.5, 4 and Hall 10 s at 48 kHz; Hall 0.5 and
Plate 4 s at 44.1 and 96 kHz).

**The low end is now a measured limit, not a promise** (review correction 2–4,
§10). Below 0.5 s the grid stops holding, because a network cannot decay faster than
its own buildup. Swept at 0.2 / 0.25 / 0.3 / 0.35 / 0.4 s:

| character | 0.2 s | 0.25 s | 0.3 s | 0.35 s | 0.4 s |
| --- | --- | --- | --- | --- | --- |
| Room @ 44.1/48 k | −2.6 / −3.6 % | −1.5 / −2.5 % | −0.1 / −1.0 % | 0.0 / −0.5 % | +1.3 / +0.1 % |
| Room @ 96 k | **−17.5 %** | −14.7 % | −11.0 % | −9.0 % | −7.6 % |
| Hall @ 44.1/48 k | **+67.5 / +67.9 %** | +37.7 / +37.8 % | +20.1 / +19.7 % | +9.3 / +8.7 % | +2.8 / +2.1 % |
| Hall @ 96 k | **+68.1 %** | +36.2 % | +16.0 % | +2.9 % | −5.7 % |
| Plate @ 44.1/48 k | +2.2 / +1.2 % | −1.5 / −1.9 % | −0.8 / −1.0 % | +0.6 / +0.5 % | +1.8 / +1.7 % |
| Plate @ 96 k | −8.1 % | −11.5 % | −10.7 % | −7.7 % | −5.8 % |

The module's DECAY minimum is therefore **the smallest value on the console's own
0.1 s grid whose measured T30 stays inside ±15 % at that rate**: Hall **0.4 s** at
every rate (its 40 ms of diffusion and 48–98 ms spacing plateau at ≈ 0.335 s, so 0.2 s
was never attainable and 0.3 s still reads +20 %); Room **0.2 s at ≤ 48 kHz and 0.3 s
above** (its fixed 5 kHz damping cutoff takes a bigger slice of the wider band at
96 kHz); Plate **0.2 s** everywhere. Rates between the measured 48 and 96 kHz take the
higher-rate value, so no floor is optimistic where it was not measured. The floors are
enforced in the constructor — see §10.

### 5.3 TONE's known clamping

The geometric law gives `fc = f0` at FLAT only while `4·f0 ≤ 0.45·fs`. Room and Hall
hit their f0 exactly at every rate. **Plate** selects 5 692 Hz at 48 kHz and
5 456 Hz at 44.1 kHz instead of 6 000 Hz (clamped `f_hi`), reaching 6 000 Hz only at
96 kHz; the delay shares the 6 kHz law and the same clamping. The law is unchanged
and the suite asserts the law as written; changing it is a design decision not taken.

### 5.4 Wet only, bypass, reset, tails, parameter changes, latency

| policy | behaviour | how it is proven |
| --- | --- | --- |
| Wet only | no dry path, no mix, no make-up, one fixed scale (1) | an impulse never appears at unity; halving the input halves the output sample-for-sample |
| Bypass | output is exact silence, the input never enters the network/line, **all state frozen** | a bypassed module writes zeros, and the frozen tail then matches an un-bypassed reference sample-for-sample |
| Reset | every line, diffuser, damping state, pre-delay ring and early history cleared | post-reset output equals a freshly built module, bit for bit |
| Tails | reverb `preDelay + 1.5·decay`; delay `repeats·time` (`repeats = ceil(60/(−20·log10 g))`, 1 at g = 0); neither cuts its own tail | both continue on silence and decay; the delay's number is asserted to be an upper bound |
| Parameter changes | **settings are read once, at construction**: a change is a new module. No smoothing, no crossfade, no pitch glide, no hidden reset — so **live TIME changes are not implemented** | a newly built module has empty state; TONE/TIME have no setter |
| Latency | `latencyFrames = 0` in both (pre-delay and delay time are effect timing) | asserted per module |

The delay's `tailSeconds` counts the loop gain alone, so it is **conservative**: at
90 % / 250 ms it promises 66 repeats, while the measured −60 dB point arrives at
about 38 because the in-loop filter removes energy too. The suite asserts the
contract is an upper bound rather than exact.

### 5.5 Stereo

- **Reverb**: one internally coupled network; both channels excite it through
  distinct weightings and are read through distinct weightings; a left-only impulse
  reaches both sides, and the left-through-left response is **not** the
  right-through-right one (proving the pair is not pre-summed). Mono builds its own
  weightings.
- **Delay**: fully independent channels, no cross-feedback.
- **Mono compatibility is not claimed**, and this task did not measure a fold-down
  sum: §16.8 says so rather than implying a result.
