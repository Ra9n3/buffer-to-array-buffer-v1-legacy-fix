## 1. Audit summary and what changed

The task was to stabilize, not to redesign. The audit therefore started by asking, for each
workflow stage, *is the layer correct* and then *is the layer actually connected*. Almost
every layer was already correct and well tested. The defects were at the **joints**.

### What the audit found

| # | Finding | Verdict |

## 4. Defects, root causes, fixes

*Naming: `S9.1.x` below are this report's **internal defect identifiers**. They are not the
`decisions-log.md` entries, which are `D9.1.1`–`D9.1.4` and cover the two fixes, the approved
selector, the deferred masking wiring and the guard change.*

### S9.1.1 — PREVIOUS and NEXT did nothing until the user first pressed Play (fixed)

**Repro.** Open ALLOY, press NEXT. The playhead stays at 0. Press Play, let it finish or press
Stop, then press NEXT: it jumps to the end.

**Root cause.** `durationFrames` started at 0 and was only written inside `startPlayback()`,
i.e. by playing. The strip's locate keys call `transport.seek(transport.durationFrames)` and
`transport.seek(transport.startFrame)`, and `seek()` is `clampFrame(frames, durationFrames)`.
With a duration of 0 both clamp to 0. The controller had no way to learn the length without
playing, so the shell had nothing to call.

**Fix.** `PlaybackController.refreshDuration()` opens the sources, computes
`sourceDurationFrames(...)` for the current mode and sets only `durationFrames` — it does not
play, pause, seek or change status. `installPlaybackShell` calls it once at install and again
whenever the project's **structure** moves. The trigger is the project's own history: an import,
a project switch and an undo/redo past a structural change all emit `clear`, while an ordinary
parameter edit emits only `record`/`merge` (verified, and pinned by a test), so a fader move
never pays for a re-measure. A refresh that fails is silent by design: a length is a
convenience, and the next Play reports anything that is genuinely wrong.

**Verification.** `9.1 · the transport knows the playable length before the first play`;
`9.1 · the playback shell measures the reopened project on install…` (which **fails** when the
shell wiring is removed — checked by reverting the fix and re-running).

### S9.1.2 — Changing the listening mode wiped the playable length (fixed)

**Repro.** Play a session to the end. Call `setSource("preview")` (MIX does the same thing when
it switches to `render`). The duration becomes 0; NEXT is dead again and the readout loses its
length.

**Root cause.** `setSource()` set `durationFrames: 0` explicitly, on the reasoning that a new
mode's length is unknown. But the length belongs to the project and the mode, not to the
previous playback attempt, and no later event recomputed it while stopped.

**Fix.** `setSource()` keeps the length, then refreshes it for the new mode (PREVIEW and RENDER
add the effect tail, so the answer legitimately differs). The position is preserved, as before.

**Verification.** `9.1 · switching the listening source keeps the playable length and the
position`; `9.1 · a source switch while playing restarts in the new mode at the same place`.

### S9.1.3 — `README.md` documented an application that no longer exists (fixed)

**Root cause.** The README was last written in Phase 0 and never revisited, while 13 tasks
landed behind it. It claimed the mini transport was inert, that playback was disconnected, that
tokens "applied to nothing", and that shared state and audio functionality were unimplemented.

**Fix.** Rewritten from verified behaviour: the real import rules (48 kHz, 24-bit PCM /
32-bit float, ≤2 channels, refusals per file), the three playback modes and their actual
reachability, MIX's behaviour and its missing masking step, both export formats with the
verified stem-sum and alignment invariants, the rulebook's honest placeholder status, and a
known-issues list that names the missing source selector, the missing export/open UI, and the
absence of any browser-level verification.

### S9.1.4 — A guard punished the act of adding a test suite (fixed, strengthened)

**Root cause.** `check-editing-structure.mjs` compared the whole `npm test` string to one
literal. Its subject is the **editing layer**; adding a suite failed it. It would also have
passed a command that silently dropped a file, as long as the string matched.

**Fix.** It now asserts the intent: the command uses the project loader and `node:test`, every
suite it names exists on disk, the Task 3.2–8.2 suites are all still present **in their
original order**, and any suite beyond that roster must be on a named sanctioned list. I
verified it still fails on **(a)** removing a required suite and **(b)** adding an
unsanctioned one — and that it names the offending file.

### Not fixed, deliberately

- **The source selector** (§7.1): was blocked by `D2.3.2`. It is now **approved** (`D9.1.2`) and
  **still not built** — implementing it is the next task's work, not this one's.
- **Masking not wired into MIX** (§7.2): a scoped feature (MIX orchestration), not a
  stabilization defect, and 7.3 explicitly deferred it.
- **No export / open UI** (§7.3, §7.4): new UI, out of bounds for this task.

## 7. Remaining known issues and deferred work

### 7.1 The listening source — **RESOLVED in Task 9.1.1**

The gap: RAW was the default, RENDER was reachable only through MIX, **PREVIEW had no control, and
after a MIX there was no way back to RAW** — contradicting plan §6 (three modes) and §10 (keep raw
and processed playback available for comparison).

**Resolved.** The owner chose option (a) — Option B plus one small, visible three-position control —
and Task 9.1.1 implements it in the persistent mini transport, with the four approved keys and MIX
untouched. Full detail, guards and tests in **§10**. Nothing about it is outstanding except a
browser click, which this environment cannot perform.

*Kept for the record:* Option B **alone** had no conflict-free mapping — the app's only five
interactive controls (PREVIOUS, PLAY, STOP, NEXT, MIX) were all committed, the two `LampDisplay`s are
display-only, and PREVIEW had no candidate control at all. STOP → RAW was considered and rejected:
`stop()` deliberately leaves the source alone, so overloading it would fuse "stop" with "change how I
listen" and lose the rendered mix the user was comparing against. That analysis is why a control had
to be added rather than bound.

### 7.2 MIX does not resolve masking

`measureMaskingSources` / `detectMaskingConflicts` / `resolveMaskingConflicts` /
`resolveMaskingAudio` are implemented and tested but **called by no application code**. The
engine accepts `maskingDynamicBands`; nothing supplies them. Consequences: MIX is a straight
render without conflict resolution, and plan §15's "Auto recalculated on rerun / Manual
preserved" is verified in the engine, **not** through the integrated path. Deferred by 7.3, and
it needs the MIX orchestration task, not a stabilization patch.

### 7.3 No export UI

`exportProject` is a complete, tested library with no caller. Needed: a destination choice
(File System Access with a download fallback), a selection (mix / stems / buses), a format
(`float32` / `pcm24`), progress, and the manifest and rulebook reporting already built.

### 7.4 No open-project UI

Autosave, lifecycle, recents and validation all exist; no control opens a project from disk.

### 7.5 No browser-level verification of anything

No browser exists in this environment, so every DOM, Web Audio, drag-and-drop, focus and
keyboard behaviour is **unverified at the UI level**, though the logic each component calls is
tested. A manual pass is required before calling the app releasable.

### 7.6 Re-import duplicates rather than detecting

The same file twice becomes two tracks with two copies of the audio (nothing is overwritten).
No requirement exists for deduplication; recorded because a user will meet it.

### 7.7 Smaller items

- A mono stem is duplicated to L/R correctly (verified), but the *engine* still has no separate
  mono gain convention; the importer's mono flag is advisory.
- Seeks are sample-accurate; there is no scrub bar on the strip (by design).
- No listening test was performed, and plan §9 defers rulebook tuning to listening tests: the
  shipped rulebook remains an honest empty placeholder.

set up Cargo workspaces, or implement native IPC"). Nothing in this task pretends otherwise.

What the native port must satisfy, and where the web build stands:

1. **Tauri + Rust only.** Rust is both the shell and the engine. No JUCE, no CMake, no
   cross-language audio bridge (plan lines 723–725).
2. **The DSP is the porting reference.** It is already pure TypeScript over sample buffers, with
   no dependency on browser filter/compressor nodes, so each module in `src/lib/dsp/`,
   `src/lib/engine/` and `src/lib/analysis/` maps onto a Rust module with a test suite as its
   specification. Web Audio is used only for output, as the plan allows.
3. **The frontend should move unchanged.** Svelte + Vite inside Tauri's webview. This is
   per-architecture: components never construct an `AudioContext` or a timer; they call
   `src/lib/playback/store.svelte.ts` (`check:transport` and `check:playback` enforce this).
4. **What must move to Rust:** asset storage (today IndexedDB, via the `AssetStore` interface —
   already an injectable seam), decoding/encoding (`wav.ts`), the DSP and engine, and the
   render/export path. Playback output becomes native audio.
5. **What must not move:** project state, history, autosave and the UI — those stay in the
   webview.
6. **Clean seams already in place:** `AssetStore` (memory/IndexedDB), `PlaybackOutput` and the
   `Clock` (injected into the controller — the shell supplies Web Audio, a fake window supplies
   stubs), `ExportDestination` (memory / collect / file system), and the pure `renderProject`
   and `exportProject` functions. Each is a small surface a Rust implementation can implement.
7. **Gaps to close before a port:** the two missing UIs (§7.3, §7.4), the masking wiring
   (§7.2), and the rulebook's deferred tuning (§7.7) — porting an unfinished workflow would
   freeze the wrong behaviour.
8. **Not in scope, per plan:** plugin hosting (CLAP as a later preference, VST3 secondary) and
   any native design that would complicate the plan's architecture.
