approved hardware language, on fixture data only: one **Return strip per
named effect return** (three in the fixture session: Room Reverb, Plate
Reverb, Delay 1 — the same returns the track strips' send slots name) and

## Rendering — how each requirement is met

### Bus-master strip
Same skeleton as a track (`StripModule`): the head prints `B1` / `BUS` /
"Mix Bus"; BUS TRIM is the orange knob the spec reserves for bus / group
masters, on the tracks' ±20 dB TRIM range so it reads the same; BALANCE is
blue-grey (pan / stereo) on the PAN range; the bay position is a blank
panel of the bay's exact height (113.3 px), so the MASTER fader starts at
the tracks' fader line (y 992.6 at 1920, same as track 01 and the Returns).
MUTE · SOLO · PEAK as on a track.

### Return-bus strips
One strip per named return in fixture data (three; the list is the
source). Each shows its **name** in the head (the engraved truncating
name, titled) and the plan §8a controls for the Console: **character**
(window print), **decay / time** (knob), **pre-delay / feedback** (knob),
**tone** (knob), **output level** (RETURN fader), **bypass** (switch with
lamp). Plan §8a's remaining chain detail belongs to the Mixer (Task 2.9).

### Identifiable as a Return without a new language
Every element is an existing Console element in an existing role: the
type print `RET` beside the number, as `TRK` sits on a track; the green
knob family that already means "sends / reverb / delay" on the tracks'
send knobs; the character window in the send slot's window recipe and
green ink, so the Returns' windows and the sends that feed them read as
one family; the fader legend RETURN where a track says LEVEL. No new
colour, shape, texture or print style was introduced; the only new CSS is
the window and two flex wrappers.

### Pinned independently of the scrolling bank
The pinned rail is a sibling of the tracks scroller, not a child; its
width is content-sized (`auto` column, `max-content` row) and it is the
only element in the bank with `overflow-x` besides the tracks rail — and
only in column mode. Measured: rail scroll 640 px moves track 01 by
−640 px and the pinned strips by 0.

### Not done, by design
No effect creation / deletion / routing / DSP / persistence; no model; no
click handler anywhere beyond the approved controls' own behaviour; no
instrument or Prominence control (Console strips exclude them, plan §3);
no screws (D2.1.9); no glow; no hex colours; nothing drawn behind print.

## Deviations, known issues, remaining work

1. **TONE in the bay, the second control in the knob section (D2.4.3).**
   The owner's chosen option read "DECAY / TIME knob, TONE knob, bay with
   CHARACTER over PRE-DELAY / FEEDBACK". Built with the approved Knob at
   the bay's half-width slot, the legend "PRE-DELAY" measures 76.4 px and
   "FEEDBACK" 73.4 px against a 71-px slot (the knob's label ellipsises;
   its width is not a prop, and the knob is never modified) — the legends
   would have truncated to "PRE-DE…" / "FEEDB…". Rather than abbreviate
   the plan's words, the two knobs trade places: the second control takes
   the full-width second knob section and TONE (36.5 px) sits under the
   character window. Same controls, same geometry; a one-line change back
   (`knobB` ↔ bay knob) if the owner prefers the original order with
   shorter legends ("PRE-DLY", "FDBK").
2. **Fewer complete track strips visible.** Real 160-px strips in place of
   ~100-px placeholders cost two track strips at 1920 / 1440 / 1280 (7 / 4 /
   3). The owner's rules — strips are fixed modules, never shrunk; the
   pinned area never scrolls away — leave no other outcome in row mode; the
   owner chose column mode for the narrow end. Fewer pinned Returns in the
   fixture would show more tracks; the owner chose three.
3. **Column mode makes the Console taller** (bank 1433 px): at 1024 and
   768 the pinned block is reached by the room's vertical scroll. Accepted
   consequence of D2.4.2.
4. **Provisional parameter ranges** (DECAY 0.2–10 s, PRE-DELAY 0–200 ms,
   TIME 20–2000 ms, FEEDBACK 0–90 %, TONE ±10) are the builder's; the
   plan names the controls, not their ranges. To be settled with the model
   (Task 3.1) and the Mixer chain detail (Task 2.9).
5. **The blank bus bay** is a plain panel of the bay's height (D2.4.4).
   Something could later live there (a bus insert, a width control); the
   slot is marked `data-blank-panel`.
6. **`ChannelStrip.svelte` (Phase 0 placeholder) is now unused**, kept
   byte-identical because the Task 2.3 guard pins it and the tokens guard
   lists it. Deletion is the owner's call; it is a one-file removal plus
   two guard lines.
7. **Guard re-pin.** `check-console-transport` pinned `ChannelBank.svelte`
   as an approved file in Task 2.3; this task changes the bank, so the hash
   was updated (comment left in the guard). The bank's new structure is

8. **Return names come from the shared list** ("Delay 1" — the plan's
