## 2. Measured, not asserted — in a real browser

The production build served; the fixture session seeded; **two synthetic
60 s 24-bit mono stems imported through the real picker** (16-bit WAVs are
rightly refused by Task 5.1's import rule — the first harness draft used
16-bit and was refused silently, which is how we found the app's rule works).
`scripts/verify101.py` (Playwright, port 4101), full log in
`task-reports/evidence/10.1/measurements.json`:

**§2 (the spec's own example).** A click at bar 3 in the first lane set the
playhead to **192000 frames — exactly** (2 bars at 120 bpm = 4.000 s), the
line at **88.0 px** (2 bars × 44 px), while stopped, without starting playback
and without recording a start (`startFrame` still 0). Pressing Play started
from bar 3 and recorded **192000** as `lastPlaybackStartPosition`.

**§1.** The line crossed at **21.2–22.0 px/s** — the tempo's own 44 px per
2 s bar (measured over 0.9 s of playback). The live position is read from the
Web Audio output's own clock (`positionFramesNow`), never a timer's guess.

**§4.** At a 1200×800 window (visible timeline 981 px, trigger 735.8 px):
the view held at **scrollLeft 0** while the playhead was left of the trigger
line; a click at bar 20 while playing (§8) re-recorded the start
(**1920000** — exactly 40 s) and engaged follow; the catch-up (240 ms) then
exact tracking measured **159.0 vs expected 159.2** and **173.0 vs 173.0** at
+600 ms and +1200 ms — the playhead held at 75% of the visible timeline to
**sub-pixel** accuracy, with no page jump (the view moved ~150 px in ~1.2 s).

**§5.** A manual scroll (view back to the start) suspended follow instantly:
badge `data-follow-suspended="manual-scroll"`, the Re-follow key present,
playback still running, the view staying at 0 (±1 px). The **F shortcut**
resumed and the view caught up to the trigger line: **211.0 vs 211.2**; a
second suspension (wheel with horizontal intent) resumed by the
**Re-follow key**: **236.0 vs 236.1**.

**§3.** Stop froze at the audio clock: `positionFrames 2123488 ==
stoppedPosition 2123488` (the freeze point), start memory untouched. With
*second-stop-returns-to-start* enabled on the real Settings screen, a second
Stop returned the playhead to **1920000 exactly** — the bar-20 locate's
memory — and `stoppedPosition` was **not** rewritten by the return. With
*return-to-start-on-stop* enabled, the first Stop returned the playhead to
**1920000 exactly**.

**The layer's geometry.** z-index **1** (above the lanes, beneath the pinned
rows at 2, the head at 3, the corner at 4); top **83.0 = the first lane's
top 83.0**; height **1600 = 20 lanes × 80**; the line spans the layer's full
height; the layer eats no pointer event; the cap is a real focusable button;
the moving element's computed `will-change: transform`.

## 3. Two real defects the measurement caught (both fixed in-task)

1. **The layer's first draft was a spanning grid child** (`grid-row: 2 /
span 20`). The grid routed every auto-placed lane AROUND it: each lane one
row below its track row — the first lane's top 80 px below the layer's top.
The layer is now an **absolute overlay** whose top is the head's own height
formula (`2 × --arrange-band-height + --arrange-tempo-height + 2px`) — the
same vars the head is built of — and the alignment measured exact (83.0 vs
83.0).
2. **`barsToSeconds` did not accumulate across tempo segments**: the first
draft returned only the last segment's seconds (44 fixture bars → 8.571 s
instead of 88.571 s). The suite's round-trip test caught it; the shipped
version accumulates, and the test pins the fixture's landmark.

## 4. What is honestly not in this task

- **Recording (§10).** `isRecording` is FALSE — ALLOY v1 has no recording path
  (the plan has none). The §10 rule (the stationary override) is implemented
  and tested synthetically; the future recorder meets it on this contract.
- **A loop UI (§7).** The region API, the wrap, the no-scroll-when-visible
  rule and the tests all exist; **no UI sets a region yet** — no loop control
  exists in ALLOY. The wrap rides the 50 ms poll, so sample-accuracy is not
  claimed (up to the poll's overshoot); looping a bounded producer from
  outside is the honest limit, said in data-model §23.
- **Zoom (§6).** No zoom control exists. The line's x is computed from the
  measured bar width each frame, so a future zoom gets §6 for free; resize
  during playback is covered by the ResizeObserver + live measurements.
- **Editing during playback (§9).** No clip editor exists in the Arrange yet.
  The suspension API (`reason: "edit"`) is the contract the editor will call;
  the tests cover it.
- **Scrub release.** One locate lands on release (a seek per pointermove
  would reopen the sources per event); audio scrubbing (hearing the scrub) is
  future work.
- **Headless audio quirk, noted for the record.** Headless Chromium can pause
  the audio clock for a few hundred ms right after begin(); the harness tests
  net advance over the window rather than per-sample monotonicity. In a real
  browser this is not observed.

## 6. The spec's acceptance criteria, one by one

| Criterion | Where it is proven |
| --- | --- |
| Clicking bar 3 and pressing Play starts from bar 3 | §2 above: 192000 exact, twice |
| Stop leaves the playhead at the stopped position by default | §3 above: 2123488 = the freeze point |
| Smooth Continuous Follow begins scrolling at 75% of the visible width | §4 above: hold at 0, then 159/173 vs 159.2/173.0 |
| The playhead never disappears while Smooth Follow is active | asserted in the harness (`visible`) and measured |
| Manual scrolling immediately suspends auto-scroll | §5 above: the badge, reason manual-scroll |
| Zooming preserves the playhead's musical position | no zoom control exists; the mapping is measured, not zoom-dependent |
| Loop playback causes no page jumps when the loop fits on screen | the pure engine's rule, tested (`followTarget` with a fitting loop returns null for every mode) |
| Each editor panel can have an independent Follow setting | §13 tested (alpha/beta/gamma/delta in the suite); one panel wired (the Arrange), the pattern is the contract |
| Playhead updates are smooth without DOM thrashing or audio dropouts | one element per frame (`will-change: transform` measured), the rAF loop only while moving; the line crossed at the tempo's own speed with the audio playing |
