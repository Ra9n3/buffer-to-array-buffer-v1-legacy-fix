## Selection behaviour

Selection is **local UI state in each room** — `let selectedId = $state(...)` in
both `ConsoleRoom` and `MixerRoom`. There is no store, no persistence, and no
cross-room synchronisation: selecting a channel in Console does not change the
Mixer's selection, and vice versa. This preserves the Task 0.5 scope boundary.

Strips are real `<button type="button">` elements with `aria-pressed`, so
selection works with mouse, Enter/Space, and assistive technology.

Verified in the live app, at 1024×768, in **both** rooms:

| Step | Console panel | Mixer panel |
| --- | --- | --- |
| Room entry | Track 01 | Track 01 |
| Click Track 07 | Track 07 | Track 07 |
| Click Delay Return | Delay Return | Delay Return |
| Strips with `aria-pressed="true"` | exactly 1 | exactly 1 |

## Correction: Mixer reverted, Console reduced

**Status: COMPLETE — awaiting explicit owner approval.**

### What I got wrong

The owner's instruction was that the channel bank should appear on **both** the
Mixer and Console tabs. I misread that as licence to restructure the Mixer, and
replaced its approved two-column layout with a stacked "details on top, bank at
the bottom" arrangement. **The owner never asked for the Mixer window to
change.** That was an unrequested change to an already-approved layout and it
has been reverted.

### Reverted — Mixer

`src/rooms/MixerRoom.svelte`, `src/components/MixerChannelStrip.svelte`,
`src/lib/mixer.ts` and `scripts/check-mixer-structure.mjs` were restored to
their exact pre-adjustment state from commit `26f0856` (the approved Task 0.5
delivery). The Mixer is back to:

- **Left**: scrollable column of 23 selectable channel strips
  (`data-mixer-region="channel-column"`), with its own "Channels" heading and
  placeholders.
- **Right**: Selected Channel & Processing Chain detail panel
  (`data-mixer-region="detail-panel"`).

It no longer uses the shared bank or the shared detail panel; it is
self-contained again, exactly as approved. `check:mixer` is back to its
original 25 guards and passes 25/25.

### Changed — Console

The Console is now exactly **two zones and nothing else**:

| Zone | Contents |
| --- | --- |
| 01 Selected channel & processing chain | shared detail panel |
| 02 Channel bank | shared channel bank, selection-capable |

**Removed from Console:**

- the **Meter bridge** zone, at the owner's request;
- the **Transport** zone and its scroll-reveal behaviour, which existed only to
  satisfy the now-removed meter/bank/transport stack. The persistent mini
  transport is Task 0.6, which is where a shared transport belongs.

The `onMount` scroll listener that toggled the transport has been removed with
it.

### Console now fits one screen with no scrolling

The requirement was that both zones appear in one window without the user having
to scroll. The Console shell is pinned to one viewport
(`[data-active-room="console"].app-shell { height: 100dvh; overflow: hidden }`),
the room fills its canvas, and the two zones share a
`minmax(0, 1fr) / minmax(15.5rem, 0.64fr)` grid.

To make that fit at short viewports without cramping, the shared detail panel
and the channel strips were compacted:

| Element | Before | After |
| --- | --- | --- |
| Detail block surface min-height | 2.75rem | 2rem |
| Tall block (EQ, compressor) min-height | 4.5rem | 3rem |
| Detail block padding / gap | 0.375rem / 0.1875rem | 0.1875rem / 0.125rem |
| Chain slot padding / gap | 2px + 1px gaps | 0 + tighter gaps |
| Channel strip slot min-height (small) | 1.75rem | 1.25rem |
| Fader slot min-height | 3rem | 2rem |
| Strip padding / gap | 0.375rem / 0.25rem | 0.3125rem / 0.1875rem |

Nothing is hidden and no label is truncated by these changes — they are spacing
and minimum-height reductions only. **The Mixer keeps the original, larger
sizing** because it reverted to its approved files and does not share these
components.
