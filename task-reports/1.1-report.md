design system — not the Alloy mixing application. Its entire route surface is:

Plan §13 and §16 lock the web-first implementation to **Svelte + TypeScript +
Vite**, explicitly avoiding SvelteKit/SSR. This repository is
**React 19 + Vite 7 + Tailwind CSS v4** (`package.json`, `src/main.tsx`).

Task 1.1 §2.A says to establish tokens "using the project's existing
conventions", and §4 says to "follow the repository's existing framework". Those
instructions and the locked decision point in different directions:

- Building tokens here means building them for React + Tailwind v4, which
  contradicts a §16 locked decision.
- Building them for Svelte means starting the real application project, which
  first requires Phase 0 (0.1 app shell) in that same project.

This needs an owner decision before 1.1 can be executed correctly. It is not mine
to resolve silently, and §17 forbids promoting a deferred/unresolved item into a
fixed requirement on my own initiative.

## Token categories implemented

None. §2.A was not started, because §1 forbids proceeding.

For reference when the task is unblocked, the foundational token material that
**already** exists and should be consolidated rather than duplicated:

- `src/index.css` — Tailwind v4 `@theme` block defining 16 colour custom
  properties (`--color-ink`, `--color-shell`, `--color-panel`, `--color-panel2`,
  `--color-alu`, `--color-walnut`, `--color-brass`, `--color-brasslite`,
  `--color-cream`, `--color-amber`, `--color-amberlite`, `--color-sred`,
  `--color-bgrey`, `--color-cgreen`, `--color-org`, `--color-parch`), three font
  families (`--font-display`, `--font-body`, `--font-mono`) and four animation
  tokens. Spacing, radii, border and shadow tokens are **not** defined; those
  values are currently inlined as utility classes.
- `src/lib/colors.ts` — the six functional colour families from plan §4 /
  hardware-reference §5 as TypeScript data, each with `base`, `hi`, `lo` and
  `ink` values plus the "applies to" meaning, and a separate `ORG_COLORS`
  organisational palette.

Gaps that 1.1 would need to close: no semantic role naming (tokens are named for
their hue, e.g. `--color-sred`, not for their role, e.g. `--color-dynamics`); no
spacing scale; no radius/border/shadow tokens; the two colour sources
(`@theme` and `colors.ts`) are not derived from one another, so they can drift.

Also worth noting for §2.B: the fonts currently referenced
("Big Shoulders Display", "IBM Plex Sans", "IBM Plex Mono") are loaded from a
Google Fonts `<link>` in `index.html`. Task 1.1 §2.A.2 and §4 forbid font
downloads and internet-dependent assets, so that would need to be resolved —
probably by moving to system-available faces — as part of the typography tokens.
